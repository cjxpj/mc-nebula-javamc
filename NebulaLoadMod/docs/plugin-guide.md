# 词库插件开发指南

> 面向**要写 `.n` 插件的人**。本文不解释桥接层怎么实现，只讲「一个插件从建目录到能跑、能调试」需要知道什么。
> 当前环境：Minecraft 1.21.11 / NeoForge 21.11.42 / Java 21。
>
> **查 API 去 [`apis/README.md`](apis/README.md)**：按 LLSE 体例组织的 130 条方法手册，按类别分篇，
> 每条都有签名、参数类型、返回值与示例；事件清单在 [`apis/事件.md`](apis/事件.md)。
> 想了解桥接实现、事件来源与构建方式看 [`neoforge.md`](neoforge.md)；JNI 契约与词库加载规则看
> [`bridge/README.md`](../../bridge/README.md)。契约表 [`mc-api-map.md`](mc-api-map.md) 面向改桥接的人。

## 0. 五分钟上手

**插件就是一个文件夹**。在专用服的 `<gameDir>/nebula/` 下建一个目录，写两个文件：

```text
<gameDir>/nebula/我的插件/
├── main.n
└── nebula.ini
```

`main.n`：

```text
// 行首 // 是注释
[f]初始化
问候:§a你好，欢迎来到星云

[f]加载
我的插件已加载

[事件]玩家聊天
如果:%消息%==你好
    $世界.提示 %玩家名% %问候%$
如果尾
```

`nebula.ini`（元数据，桥接层**不读取**，只是留档）：

```ini
名称 = 我的插件
作者 = me
地址 =
版本 = 1.0.0
描述 = 第一个星云插件
```

然后进游戏或控制台：

```text
/nebula load 我的插件       ← 首次加载
/nebula list                ← 确认已加载
```

在聊天里发「你好」，会收到私聊提示。改完词库用 `/nebula load 我的插件` 生效；开发时开
`/nebula debug 我的插件`，之后**保存文件就会自动重编译**，不用反复敲命令。

> `main.n` 优先作为入口；同目录顶层的其它 `.n` 会自动合并进同一个命名空间，所以大插件可以拆成
> `界面.n` / `配置.n` / `商品.n`（参考泥土商店）。`_[开头]` 或 `.[开头]` 的目录会被禁用。

## 1. 词条与语法速查

词库是**布局敏感**的：一个词条 = 一行「头」+ 紧随其后的正文行，词条之间用**块外空行**分隔。
正文行**顶格写**，缩进只用在 `如果` / `否则` / `遍历` / `点击:[函数]` 这些块的**内部**；
块必须闭合（`如果尾` / `结束`），漏一个整个插件编译失败。

| 写法 | 含义 |
| --- | --- |
| `名:值` | 变量赋值。值可以是文本、`%变量%`、`$调用$` 或 `[%a%+%b%]`；赋原样 JSON 用 `名::{...}`（见第 7 节） |
| 裸文本行 | 输出一行（事件里的输出会被宿主广播 / 回给玩家） |
| `%名%` | 取变量；`%对象.字段%` 取 JSON 字段，如 `%玩家.名称%`、`%配置.货币%` |
| `$函数 参数…$` | 调用内置函数 / 自定义函数 / `世界` 方法，**结尾的 `$` 不能漏** |
| `[%a%+%b%]` | 数值运算（也支持 `-` `*` `/`），如 `总额:[%单%*%量%]` |
| `// 注释` | 行注释 |
| `"带空格的文本"` | 用双引号包住含空格的实参，如 `"§7余额：§a%余% 个泥土"` |

条件与循环（**必须闭合**，否则整个插件编译失败）：

```text
如果:%消息%==帮助
    $世界.提示 %玩家名% 用法：/签到$
否则如果:%消息%==余额
    ...
否则
    ...
如果尾

遍历:i,件=%表%
    $世界.界面物品 %面% %件.槽% %件.物品% 1$
结束
```

比较符实测可用：`==`、`!=`、`>`、`<`。函数与返回：

```text
[函数]查余额 玩家 货币
余:$世界.取物品数 %玩家% %货币%$
返回 %余%

[指令]商店
余:$查余额 %玩家名% minecraft:dirt$
```

- `[函数]名 参数A 参数B` 定义函数，调用写 `$名 值A 值B$`，函数体内用 `%参数A%`。
- `返回 内容` 产生返回值；裸 `返回` 直接结束且不输出。
- `[G]名字` 是公开函数（只改可见性，**不是**全局变量），`[f]名字` 是私有 / 生命周期函数。
- **一行只能写一个 `$调用$`**；赋值行里最多一个。需要串联就拆成多行用中间变量。
- 常用的内置函数：`$读文件 路径$`、`$JSON判断 文本$`、`$JSON键读 文本 键$`、
  `$JSON键存 文本 键 值$`、`$去除左右 文本$`、`$文本长度 文本$`、`$数字格式化 数 位数$`、
  `$引用 函数名$`。
- JSON 作为实参时**不要带空格**（`{"货币":"minecraft:dirt"}`），否则会被按空格切参数。

## 2. 生命周期钩子（最容易写错的地方）

| 钩子 | 什么时候跑 | 该放什么 |
| --- | --- | --- |
| `[f]初始化`（编译前另有 `@头部` 触发） | **每次编译**：load / loadAll / debug 自动重编译 | 配置默认值、读 JSON、状态初始化、`$世界.注册指令$` |
| `[f]加载` | 仅 `/nebula load` 与开服 `loadAll`（插件首次插入） | 「插件已就绪」这类只提示一次的文案 |
| `[f]自检` | 词库侧约定的词条（连锁砍树里有） | 打印插件状态；`/nebula` **没有**对应子命令 |

三个高频误解：

1. **「初始化只跑一次」是错的**。它每次编译都跑，所以注册指令必须幂等（宿主侧已做去重），
   别在这里累加计数或写一次性副作用。
2. **`[f]加载` 只在插件第一次插入时跑**，所以「已加载」提示放在这里是对的。
   之后改词库只要再 `/nebula load <插件>`（重编译 + 跑 `[f]初始化`），没有单独的 reload 指令。
3. **没有 `[f]卸载` 钩子了**。卸载由**加载器**按插件归属接管：指令、界面对象、生物对象、
   事件订阅、资源包条目都会自动回收；`ServerStoppingEvent` 直接销毁引擎，也不需要保存状态。
   要持久化就写文件。

第四条，是 0.4.0 实测出来的坑：**`[f]初始化` 正文里 `变量:$调用$` 的赋值不落地。**

```text
[f]初始化
剑:$世界.注册物品 nebula:star_sword$     ← 剑 取不到对象，下面这行等于空调用
$剑.生效$
```

表现是「编译成功、零诊断、但东西没注册」。原因是初始化帧里这种赋值语句不生效，
变量没有值，后续 `$剑.生效$` 自然调不到对象。

**边界要说准**：

- **不用接返回值**就不用函数 —— `$世界.注册物品 <配置.json>$`、`$世界.注册指令 …$`
  这类只触发副作用的，直接写在初始化里完全正常。
- **要用变量接住**（`剑:$世界.创建界面 …$` → `$剑.设 …$` → `$剑.生效$`）就必须放进 `[函数]`，由初始化调用。

> 注意：Tab 页眉 / 侧边栏显示 / 世界里召唤过的实体是**玩家可见状态**，加载器不知道插件设过什么，
> 卸载后会残留到下一次 `load` 或玩家重进服。需要立即复原就在 `[f]加载` 里重设一遍，别指望卸载钩子。

调试自动重编译只跑 `初始化`，不会跑 `加载` / `重载` / `卸载`。

## 3. 作用域：配置为什么总要传参

这是写多文件插件时最常卡住的一点：

- **事件帧**的父作用域是 `plugin.state`，能读到 `[f]初始化` 里赋的配置变量。
- **`[函数]` 帧**的父作用域是词库 root，**不继承调用方作用域**——既读不到事件里的 `%玩家%`，
  也读不到运行时配置。配置、玩家名、选中数据都要**显式传参**。

```text
[事件]方块破坏
// 错：函数里读不到 %玩家% 和 %上限%
结果:$砍伐 %方块%$

// 对：把需要的东西都作为参数传进去
结果:$砍伐 %方块% %玩家.名称% %上限%$
```

唯一例外是**闭包**：`点击:[函数] … 结束` 定义的函数值会按值捕获当时的局部变量，
点击时这些变量还在（见第 7 节）。

## 3.1 尾部参数可以省略

`$世界.xxx …$` 是按位置传实参的。`world-specs.json` 里写了 `default` 的**尾部参数**可以不写，
例如 `$世界.给予物品 Steve minecraft:diamond$` 等价于数量 1，
`$世界.加效果 Steve minecraft:speed$` 等价于 30 秒 / 1 级。
**不要省略中间参数**：`$世界.加效果 Steve minecraft:speed 1$` 里的 `1` 会被当成「秒」，
而不是「等级」。完整清单与默认值见 [`mc-api-map.md`](mc-api-map.md) 第 0 节的
「可选尾参」表。

## 4. 事件与变量

当前宿主**内置 6 个中文事件**（下表）；另有 **8 个中文别名词条**（7 个玩家交互 +
玩家退出，见 4.1），不用写 Java 类名；其它事件走**通用事件桥**，用 Java 事件简名订阅
NeoForge 总线上的 267 个事件，见 [`apis/事件.md`](apis/事件.md)。

| 词条 | 触发 | 主要变量 | 可取消 |
| --- | --- | --- | --- |
| `[事件]玩家聊天` | 玩家发言 | `%玩家%`（JSON）/ `%玩家名%` / `%消息%` / `%管理员%` / `%潜行%` / `%维度%` / `%x%` `%y%` `%z%` | 是 |
| `[事件]实体受伤` | 实体掉血后（任意来源） | `%攻击者%` / `%攻击者名%` / `%实体%` / `%实体名%` / `%伤害%` / `%剩余%` / `%最大血量%` / `%身高%` / `%暴击%` / `%原因%` / `%致死%` | 否（伤害已结算） |
| `[事件]实体治疗` | 实体回血且未满血 | `%实体%` / `%实体名%` / `%数值%` / `%之前%` / `%剩余%` / `%最大血量%` / `%身高%` / `%原因%` / `%满血%` | 否（回血已发生） |
| `[事件]方块破坏` | 玩家破坏方块 | `%玩家%`（含 `.手持物品.名称%`）/ `%玩家名%` / `%方块%`（`.名称%` / `.数据%` / `.维度%`）/ `%坐标%` / `%工具%` / `%模式%` / `%维度%` / `%x%` `%y%` `%z%` | 是 |
| `[事件]玩家进入` | 每次连接成功（含重连） | `%玩家%`（JSON）/ `%玩家名%` / `%管理员%` / `%维度%` | 否 |
| `[事件]每秒` | 每 20 tick（约 1 秒） | `%服务器tick%` / `%在线人数%` | 否 |

- 玩家、实体、方块这类变量是 **JSON 对象**，用 `%玩家.名称%`、`%方块.名称%` 取字段。
- 想取消事件：$世界.取消事件$（聊天 / 方块破坏有效）。
- **事件里的裸文本行会被宿主广播 / 回给玩家**；只想让某个玩家看到，用 `$世界.提示 玩家 文本$`。
- payload 只含基础类型与 JSON，拿不到 Java 对象；别试图跨线程持有任何东西。

### 4.1 中文交互事件（推荐写法）

玩家左右键交互不必写 Java 类名，直接用中文词条名，payload 也全是中文键：

| 词条 | 对应事件 | 触发 |
| --- | --- | --- |
| `[事件]右键物品` | `PlayerInteractEvent.RightClickItem` | 使用物品（右键） |
| `[事件]右键方块` | `PlayerInteractEvent.RightClickBlock` | 右键点方块 |
| `[事件]右键空气` | `PlayerInteractEvent.RightClickEmpty` | 右键没命中 |
| `[事件]左键方块` | `PlayerInteractEvent.LeftClickBlock` | 左键点方块 |
| `[事件]左键空气` | `PlayerInteractEvent.LeftClickEmpty` | 左键没命中 |
| `[事件]右键实体` | `PlayerInteractEvent.EntityInteract` | 右键点实体 |
| `[事件]右键实体部位` | `PlayerInteractEvent.EntityInteractSpecific` | 右键点实体部位 |

另外 `[事件]玩家退出` → `PlayerEvent.PlayerLoggedOutEvent` 也走同一张别名表
（玩家离线时撤掉侧边栏数据），变量与其它玩家类事件一致。

中文变量：`%玩家名%` / `%玩家%` / `%维度%` / `%x%` `%y%` `%z%` / `%物品%` / `%数量%` /
`%手%`（主手、副手）/ `%主手%`（是、否）/ `%方块x%` `%方块y%` `%方块z%` / `%坐标%` /
`%面%`（上 下 北 南 东 西）/ `%面英文%` / `%目标%` / `%目标名%` / `%事件名%`。
英文键（`%entity.name%` 等）仍保留，但新插件建议全用中文。

```text
[事件]右键物品
人:%玩家名%
物:%物品%
$世界.提示 %人% 你拿着 %物%$
```

中文名来自事件清单的 `cnNames`（**旧 jar 不认**，会静默不触发）；同一个事件别中英
各写一个词条头，否则一次交互分发两遍。完整变量对照见
[`apis/事件.md`](apis/事件.md) 的「中文交互事件」。

**想接上表与交互事件之外的事件**，直接写 Java 类名，宿主按订阅动态注册监听器：

```text
[事件]EntityJoinLevelEvent
$世界.提示 %entity.name% 欢迎$
```

字段名来自 Java getter（`getEntity()` → `%entity%`），内置事件仍用中文名。高频 tick 事件
被节流到每秒一次，加载期事件收不到——规则与完整清单见
[`apis/事件.md`](apis/事件.md) 的「通用事件桥」一节。改完词库 `/nebula load <插件>`
就会刷新订阅表，不用重启服务端。

## 5. 调用 `世界` 原语

语法是 `$世界.方法 参数…$`。

```text
余:$世界.取物品数 %玩家名% minecraft:dirt$      ← 查询：立即返回结果，可以赋值
$世界.给物品 %玩家名% minecraft:diamond 3$       ← 动作：排队，dispatch 返回后才落地
$世界.提示 %玩家名% §a已发放$
```

**动作是延迟执行的**：同一词条里 `$世界.设方块 …$` 之后立刻 `$世界.取方块 …$` 读到的还是旧值，
要到下一次事件 / 重编译才生效。写成「先查 → 再改 → 立刻回读验证」会得到假失败，验证请换一次
事件或用宿主的查询接口。

常用方法速查（完整 128 个按类别分篇在 [`apis/`](apis/README.md)）：

| 用途 | 方法 |
| --- | --- |
| 私聊 / 动作栏 / 标题 | `提示`、`动作栏`、`标题` |
| 飘字（RPG 伤害数字 / 全息文字） | `悬浮字` |
| 音效 / 粒子 | `音效`、`生成粒子` |
| 物品 | `给物品`、`扣物品`、`取物品数`、`取背包物品`、`设背包物品` |
| 玩家 | `取玩家状态`、`取玩家列表`、`传送玩家`、`设置模式`、`加效果`、`玩家加标签`、`设置Tab列表` |
| 方块 | `取方块`、`设方块`、`设方块状态`、`填充区域`、`破坏方块`、`取相邻方块` |
| 世界 | `取时间` / `设时间`、`设难度`、`设游戏规则`、`执行命令`、`广播` |
| 指令 / 界面 | `注册指令`、`注销指令`、`创建界面`、`界面物品`、`打开界面`、`关闭界面` |

几个真机踩过的坑：

- **玩家目标用名字**：`give` / `experience` / `effect` 这类命令会拒绝 UUID 字面量，
  统一用 `%玩家名%` 或 `%玩家.名称%`，别传 `%玩家.uuid%`。
- **`$世界.执行命令 say …$` 有 256 字符上限**：`取实体列表` 这类长结果要么传 `上限`，要么分批。
- **未加载区块的方块查询返回空**：先 `$世界.区块已加载$` 判断，或让管理员 `/forceload add`。
- `%时间%` / `%版本%` 是引擎内置变量，词库里同名赋值会被遮蔽，变量名加前缀（如 `%SC时刻%`）。

## 6. 插件指令

指令由**词库自己注册**，不写进 `nebula.ini`：

```text
[f]初始化
$世界.注册指令 签到 0 sign$

[指令]签到|sign
参:$去除左右 %参数%$
如果:%参%==帮助
    $世界.提示 %玩家名% "§7/签到 领一份见面礼"$
    返回
如果尾
```

- `注册指令 规范名 [权限 0~4] 别名… [参数=值,值…]`；规范名决定 `%指令%` 的值（用 `/sign` 进来也是「签到」）。
  `参数=` 必须写在最后，逗号分隔；它把每个值注册成一个 literal 子节点，**只影响客户端 Tab 补全**
  （`/商店 ` 能看到「帮助」「余额」），命中后该值原样进 `%参数%`，词库判断不用改。
- `[指令]规范名|别名1|别名2` 头里列出所有入口，宿主按规范名匹配后**只跑命中的那一条**；
  没有 `[指令]` 词条时返回 `ok=false`，不会回退到统一事件。
- 指令词条里可用变量：`%玩家%` / `%玩家名%` / `%指令%`（规范名）/ `%参数%`（玩家输入的整串）/ `%管理员%`。
- 重复注册是幂等的；**改名 / 删名后的旧入口由加载器自动下线**（每次编译按批次对账，不需要写注销，也不用重启）。
- 执行结果的输出行会回给执行者；控制台执行也一样。

## 7. 配置与数据文件

配置文件放插件同目录，用 `%库目录%` 定位（编译时由桥接层注入到词库 root，函数帧也能读）：

```text
[函数]默认配置
文::{"货币":"minecraft:dirt","货币名":"泥土"}
%文%

[函数]配置数据
文:$读文件 %库目录%/配置.json$
如果:$JSON判断 %文%$!=true
    文:$默认配置$
如果尾
%文%

[f]初始化
配置:$配置数据$
```

- `文::{"a":1}` 这种**双冒号**写法用来赋一段原样 JSON（单冒号会把内容当表达式）。
- `$读文件 路径 [默认值]$` 读整份文件；JSON 不要带空格以免被切参数。
- `$JSON判断$` / `$JSON键读$` / `$JSON键存$` 用来校验、取字段、改字段。
- `.json` 和 `.n` 一起纳入 debug 指纹，改配置也会自动重载；没开 debug 就 `/nebula load <插件>`。
- 文件缺失或非法 JSON 时给内置默认值，别让插件整个起不来。

### 7.1 资源：图片 / 模型 / 语言文件

插件目录下的 **`资源/`** 会被 `NebulaPack` 翻译成标准资源包路径，随服下发给客户端。
目录按**资源类型**用中文分，不用记 `assets/` 那套嵌套：

```text
nebula/箱子生物/
├── main.n
└── 资源/
    ├── 物品列表/chest_creature_spawn_egg.json      → assets/nebula/items/item/…
    ├── 物品模型/chest_creature_spawn_egg.json      → assets/nebula/models/item/…
    ├── 物品材质/chest_creature_spawn_egg.png       → assets/nebula/textures/item/…
    ├── 方块状态/chest_creature_body.json           → assets/nebula_bridge/blockstates/…
    ├── 方块模型/chest_creature_body.json           → assets/nebula_bridge/models/block/…
    └── 实体材质/chest_creature.png                 → assets/nebula_bridge/textures/entity/…
```

| 资源类型目录 | 包内路径 | 默认命名空间 |
| --- | --- | --- |
| `物品列表` | `items/item/` | `nebula` |
| `物品模型` | `models/item/` | `nebula` |
| `物品材质` | `textures/item/` | `nebula` |
| `方块状态` | `blockstates/` | `nebula_bridge` |
| `方块模型` | `models/block/` | `nebula_bridge` |
| `方块材质` | `textures/block/` | `nebula_bridge` |
| `实体材质` | `textures/entity/` | `nebula_bridge` |
| `粒子` / `音效` / `语言` / `界面` | `particles/` `sounds/` `lang/` `textures/gui/` | `nebula_bridge` |
| `客户端` | `client/` | `nebula` |

- `物品列表` 落到 `items/item/`，因为物品的 `item_model` 组件统一写 `nebula:item/<名字>`。
- **方块模型只能引用 `方块材质/`（`textures/block/`）的贴图**：方块图集只自动收 `block/`、`item/` 两个目录，
  引用 `实体材质/`（`textures/entity/`）会报 `Missing textures in model …` 并渲染成品红/黑的缺图格。
  `实体材质/` 是给实体模型（`EntityModel` + `LayerDefinition`）用的。
- 表里没有的类型，可以走「原样命名空间」：`资源/<命名空间>/…` → `assets/<命名空间>/…`（例如 `资源/nebula/font/…`）。
- **只认 `资源/`**：插件根目录下的 `assets/` 不会被扫描；资源包由 mod 在开服时收集所有插件的 `资源/` 生成，没有共享底板目录。
- `pack.mcmeta` 由 mod 内建，词库目录里不需要放资源包骨架；同名资源按插件目录名排序先到先得，重名会记 WARN。
- 一个插件的 `资源/` 都没有时，mod 不生成也不投送资源包（服务器照常运行，纯原版外观）。
- **改完资源必须重启服务端**（资源包在启动时打包，sha 变了客户端才会重下）；只改 `.n` 用 `/nebula load`。
- 打包按条目名排序、时间戳固定，所以**包内路径不变时 sha1 一定不变**——挪目录、改目录名不会让玩家重下。

### 7.2 客户端声明（`资源/客户端/*.json`）

客户端 mod 里没有任何写死的外观或文案。插件把客户端表现写进 `资源/客户端/<名字>.json`，
`NebulaPack` 打成 `assets/nebula/client/*.json` 随资源包下发，客户端 `ClientDecls` 合并后读取：

```json
{
  "更新提示": {
    "开关": "是",
    "端口": 25568,
    "GitHub": "https://github.com/<owner>/<repo>/releases/tag/v{版本}",
    "文案": "§d[星云] §fmod 有新版本 §e{版本} §7（当前 §f{本地}§7）"
  }
}
```

- `更新提示`：开关为 `否` 或整块缺失时客户端完全不做版本检查；文案的 `{版本}` / `{本地}` 由 mod 填值。
  `端口` 是客户端拉 `/nebula/mod/manifest.json` 的 HTTP 端口（默认 25568）。
- **`GitHub`（0.9.1 起）决定点击后去哪**：写了就打开这个地址（支持 `{版本}` 占位，
  `releases/tag/v{版本}` 精确落到该版本、`releases/latest` 永远跟最新）；没写才退回服务端
  `/nebula/mod/latest.jar` 直链。版本检查本身仍走服务端 manifest —— 那里知道"最新版是多少"。
- **下载链接的地址不用手配**：客户端拿「玩家自己连服用的地址 + 上面的端口」去拉 manifest，
  服务端返回的 `url` 也按请求头 `Host` 回写，所以局域网、公网域名、frp 隧道、`localhost` 各自点开都是自己那条路。
  只有 `config/nebula-bridge/pack.properties` 里**显式**写了 `host=` 时才以配置为准（资源包下载也用同一个地址）。
- `实体外观`：一般**不用手写** —— 生物用 `$怪.外观$` 声明后，宿主会按槽位自动派生
  `assets/nebula/client/mob_<槽位>.json`（key 是 `nebula_bridge:mob_<槽位>`，因为品种 id 是服务端 NBT，
  客户端拿不到）。手写只用于给**非 Nebula 注册**的实体换外观。
- **文件名必须是 ASCII**：只允许小写字母 / 数字 / `_` / `-` / `.`。原版 `FilePackResources` 会把含中文的路径
  **整条丢弃**，只在客户端日志留一行 `Invalid path in datapack: nebula:client/mob_箱子生物.json, ignoring`——
  那份声明等于不存在（外观看不见、更新提示失效，而且不报错）。`NebulaPack` 会把非法名兜底改写成
  `<slug>_<短哈希>.json` 并打 WARN，但请直接写英文名（如 `appearance.json` / `join.json`）。
- 多个插件都写了 `资源/客户端/` 时按目录名合并，先写到的键优先。
- 改完声明要重启服务端（资源包 sha 变了客户端才会重下）；进服时 `ClientDecls` 会重新读一遍。

### 7.2.1 生物外观与动画

生物的造型不手写 `实体外观`，而是用**生物对象方法**声明，宿主按槽位派生进 §7.2 那份声明：

```
怪:$世界.注册生物 nebula:chest_creature$
$怪.外观 方块 nebula_bridge:mob_body_0 nebula_bridge:block/chest_creature -0.5 0 -0.5 0.45$
$怪.动画 弹跳 0.14$
$怪.动画 前倾 80$
$怪.动画 开盖 100$
$怪.动画 开合 0.18$
$怪.生效$
```

`$怪.外观$` 的参数是：`方式(只有「方块」) 方块模型 贴图 偏移x 偏移y 偏移z 阴影`。
第二个参数（方块模型）由宿主按槽位决定 —— 外观方块是编译期全量注册的，名字只能按槽位派生
（体型档 × 每档 8 个，`small` 的起始槽位是 8），写别的名字不会生效、只在 `latest.log` 打一行 WARN；
**贴图**要落在 `资源/方块材质/<名字>.png`，引用写 `命名空间:block/<名字>`。

**能改的是「贴哪张图、偏移、阴影、动画」，造型也能声明**（0.7.0 起）：

```
$怪.造型 体 1 0 1 15 14 15$      # 1/16 格坐标，0..16，可小数
$怪.造型 盖 1 14 1 15 16 15$
$怪.贴图 体 上 0 12 16 16$       # 面 = 北/南/东/西/上/下/全部
```

- 两个盒子独立覆盖，写哪个改哪个；不写就是「箱体 + 盖子」的缺省几何。
- **碰撞箱默认仍按 `体型` 档**；想让它跟着造型走就写 `$怪.设 碰撞箱 自动$`，或直接给 `宽,高`
  （`$怪.设 碰撞箱 0.6,0.9$`）。碰撞箱影响寻路、穿门、挤压，不跟着改就会出现「看着能过、实际过不去」。
- 开盖铰链 = 盖子顶面（`y = 盖.to.y / 16`）+ 方块后边界（`z = 1.0`）—— 改盖子高度会自动跟随。
- 缺省 UV：体四面整图 / 上下取贴图底部 4 行；盖四面与上取顶部 3 行 / 下取底部 4 行。
  UV 是 0..16 的贴图坐标（允许 -32..32 平铺），超出贴图不报错、只会画拉伸。

**多张贴图**（0.8.0 起）：主贴图（`$怪.外观$` 第 3 参）始终是模型槽位 `crate`；要额外的图先注册名字：

```
$怪.材质 眼睛 nebula_bridge:block/chest_eye$
$怪.贴图 体 北 0 0 16 16 眼睛$      # 第 7 参 = 这一面用哪个材质
```

材质名是词库别名，宿主按字母序编成 `t0`/`t1`…（槽位名必须 ASCII）；写错名字会退回主贴图并在日志 WARN。

| `$怪.动画$` 键 | 含义 | 缺省 | 生效端 |
| --- | --- | --- | --- |
| `弹跳` | 走路时每步抬起的高度（格） | `0.14` | 客户端 |
| `前倾` | 跳起时向前点头的最大角度 | `80` | 客户端 |
| `开盖` | 盖子全开时转过的角度 | `100` | 客户端 |
| `开合` | 每 tick 的开合进度步进，越小越慢 | `0.18` | 服务端 |
| `摇摆` | 走路时左右摆动的最大角度（度），站着不动归零 | `0` | 客户端 |
| `缩放` | 呼吸缩放倍率，`1` = 不动（一个来回约 2 秒） | `1` | 客户端 |
| `旋转` | 每秒自转多少度（浮游 / 旋风类造型） | `0` | 客户端 |
| `浮空` | 整体抬高多少格（漂浮生物，不随走路变化） | `0` | 客户端 |

- **开盖只对容器生物生效**（`$怪.设 容器格数 n$` 且 n>0）：玩家右键打开容器时盖子转开，
  关界面 / 走出 `容器距离` / 掉线都会自动合上（走的是 `ChestMenu` 的 startOpen/stopOpen）。
- **`$怪.设 容器距离 n$` 控制交互距离**（格，钳到 1..64，缺省 8）：玩家离得比这远，界面一开就关。
  0.6.6 起生效（之前 `DynamicMob#stillValid` 写死 8 格）；改完 `/nebula load <插件>` 即生效，
  已经开着的界面要重开一次。
- **弹跳对所有生物生效**，幅度乘行走速度 —— 刚起步和快停下时自然收小，站着不动高度归零。
- 八项全部可省，省了就吃缺省值（`摇摆`/`缩放`/`旋转`/`浮空` 的缺省都是「不起作用」）。**调这八个数不用换客户端 jar**（声明走资源包）。
- 造型拆成「箱体 + 盖子」是因为方块模型是一次性提交的整体几何，转不了其中一部分；
  宿主已经为你把 `mob_body_<槽位>` 和 `mob_lid_<槽位>` 都派生了，插件只需要给一张贴图。

#### 刷怪蛋与创造页（`$怪.加物品$`）

```
$怪.加物品 用途 基底 标记 名称 [模型] [贴图] [堆叠] [创造页] [颜色]$
```

- `用途=刷怪蛋` 时宿主会把基底换成 `nebula_bridge:spawn_egg` + `entity_data` 组件，于是它是**真 `SpawnEggItem`**：
  右键方块走原版 `useOn`（落点 / 扣 1 颗 / 音效 / 发射器 / 改名传递全白拿），**不需要写任何右键事件**。
  只有在想自己控制落点或加生成特效时，才挂 `[事件]右键方块` + `$世界.刷怪蛋生成$`。
- `模型` 决定 item definition 指向哪份 `models/item/<名字>.json`；`贴图` 决定那个模型用哪张 PNG，
  两者可以不同（一张图给多件物品用）。`贴图` 省略时按 `模型` 推导，写 `xxx` / `item/xxx` /
  `nebula:xxx` / `nebula:item/xxx` 都认，统一成 `命名空间:item/xxx`。
- `创造页` 写 `生成蛋` 进原版「生成蛋」页；写别的值进「星云物品」页。

#### AI 目标（`$怪.目标$`）

生物出厂只会「浮水 + 张望 + 8 格看玩家」。要攻击 / 逃跑就声明目标：

```
$怪.目标 注视 玩家 12$         # 类型 对象 距离
$怪.目标 攻击 玩家 1.1 16$     # 对象 速度 索敌距离
$怪.目标 逃跑 玩家 8 1.4$      # 对象 触发距离 逃跑速度
$怪.目标 恐慌 1.2$             # 受伤后逃跑速度
$怪.目标 漂浮$                 # 常驻 FloatGoal（已内置）
```

- 只做**原版 Goal 的参数装配**（`MeleeAttackGoal` / `AvoidEntityGoal` / `PanicGoal` /
  `LookAtPlayerGoal` / `NearestAttackableTargetGoal`），路径与冷却全跟原版一致。
- 「对象」认 `玩家` / `怪物` / `动物`。
- ⚠️ 攻击 / 逃跑 / 恐慌 会自己 `moveTo`，**与 `$世界.巡逻$` 抢腿**：二选一，别同时用。

#### 右键交互与掉落

```
$怪.交互 开容器$                    # 缺省；或有容器就开菜单
$怪.交互 无$                        # 交还给 [事件]右键实体
$怪.交互 给予 minecraft:apple 3$    # 右键给 3 个（10 tick 冷却，防连点刷物品）
$怪.掉落 minecraft:gold_nugget 0.5 2$   # 死亡按 50% 掉 2 个
$怪.掉落 minecraft:stick$              # 不写概率 = 必掉
```

`$怪.掉落$` 与 `$怪.设 死亡掉落$`（管容器内容撒不撒）互不影响。

### 7.3 自定义物品：一件一个配置文件

物品**不写在 `main.n` 里**，放在 `定义/` 下，一个 `.json` 一件：

```json
{
  "名称": "星云剑",
  "基底": "minecraft:diamond_sword",
  "颜色": "light_purple",
  "稀有度": "epic",
  "耐久": 500,
  "外观": "star_sword",
  "描述": [
    { "文本": "攻击力 11 · 右键：星光斩", "颜色": "gray" }
  ],
  "属性": [
    { "属性": "minecraft:attack_damage", "数值": 10.0, "运算": "add_value", "槽位": "mainhand" }
  ]
}
```

`main.n` 里一件物品一个函数，读文件与设值都在词库这边：

```text
[f]初始化
$注册剑 %库目录%$

[函数]注册剑 库
剑文:$读文件 %库%/定义/star_sword.json$
剑:$世界.注册物品 nebula:star_sword$
$剑.载入 %剑文%$
$剑.生效$
```

两条实测出来的约束：

- **要接住对象（`剑:$…$`）就得在函数帧里** —— `[f]初始化` 正文的赋值不落地。
- **一件物品一个函数**：`$读文件$` 的返回值含换行，和别的物品挤在同一个函数里会吞掉后面的语句，
  表现是「只注册了第一件，其余静默不执行」。分开写互不影响，配置文件也不用压成单行。

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `物品` | 否 | **已不需要**：id 由 `$世界.注册物品 x$` 那一行决定（`x` 可省略 `nebula:` 前缀） |
| `名称` / `基底` | 是 | 名称与**原版**基底物品 id |
| `外观` | 否 | 贴图名：派生 `items/item/<名>.json` 与 `models/item/<名>.json`，贴图取 `资源/物品材质/<名>.png`；也接受 `nebula:item/xxx` 全名 |
| `颜色` / `稀有度` | 否 | `light_purple` / `epic` 这类原版枚举名，写错就当没写 |
| `堆叠` / `耐久` | 否 | 有 `耐久` 时强制单件堆叠 |
| `描述` / `属性` / `食物` | 否 | 数组或对象，见 `物品/定义/` 里的现成例子 |

- **成品去处是创造模式的「星云物品」一栏**，注册什么就在那一栏出现什么；不再散到原版各页，也不需要指令发放。
- **加一件物品 = 加一个配置文件 + 一个注册函数 + 初始化里一行调用**；删物品把这几处一起去掉，
  本批没声明的物品由批次对账自动下线（日志会写 `物品下线：<id>`），不需要写注销。
- 配置里的 `[ ]` `"` 不会被词库语法碰到 —— 这正是把它挪出 `.n` 的好处（词库实参按空格切、含 `]` 要转义）。

### 7.4 什么时候需要换客户端 jar

内容（词库、物品定义、贴图、界面、文案）全部由服务端在运行期下发，**改这些不用换客户端**。
只有改**注册表条目**才必须两端同版本 —— NeoForge 握手会逐个比对注册表，服务端多一个条目客户端就进不来。

| 改了什么 | 客户端要换吗 |
| --- | --- |
| `定义/*.json`、`main.n`、`资源/` | 不要，`/nebula load` 即可 |
| `ItemRegistry` / `CreativeItems` / `MobRegistry` 等运行期逻辑 | 不要 |
| `NebulaEntities` / `NebulaBlocks` / `NebulaCreativeTab`（注册项） | **要** |
| `src/client/` 渲染器、`*Payload` 网络包 | **要** |

构建时看这一行就够了：

```text
Registry: unchanged (3e5aeff33940) - client jar NOT required
Registry: CHANGED (xxxxxxxxxxxx) - both sides need the same jar
```

它算的是「声明注册项的三个源文件的指纹」，与内容改动无关，所以改词库永远显示 `unchanged`。

当前注册项池的容量上限，**写满要扩容，那也属于“要换”**：
生物槽位 32（tiny/small/normal/large 各 8）、外观方块 32、创造页 1 个（`nebula:items`，所有物品共用）。

## 8. 界面与点击闭包

界面是**对象**：`创建界面` 返回 id，后续操作都带这个 id，点击逻辑写成函数值交给 `打开界面`。

```text
[函数]画菜单 玩家
面:$世界.创建界面 %玩家% 3 §a我的菜单$
$世界.界面物品 %面% 11 minecraft:lime_stained_glass_pane 1 "§a领取" "§7点一下" 是$
$世界.界面物品 %面% 15 minecraft:barrier 1 "§c关闭"$
点击:[函数]
    点:%参数1%
    槽:%点.槽位%
    如果:%槽%==11
        $世界.给物品 %玩家% minecraft:bread 4$
        $世界.提示 %玩家% §a已领取$
        $世界.关闭界面 %面%$
        返回
    如果尾
    如果:%槽%==15
        $世界.关闭界面 %面%$
        返回
    如果尾
结束
$世界.打开界面 %面% %点击%$
```

- `界面物品 面 槽位 物品 数量 名称 说明 [发光]`；说明里用 `|` 换行。
- `点击:[函数] … 结束` 是**闭包**，按值捕获定义时的局部变量（`面` / `玩家` / `配置` / `表` 点击时都还在），
  不用再塞「界面数据」或全局状态表。
- 宿主点击时把 `玩家名 / 界面 / 槽位 / 按钮 / 动作 / 区域 / 物品 / 数量 / 数据 + 玩家快照`
  组成 JSON 作为闭包的 `%参数1%`，先 `点:%参数1%` 再用 `%点.槽位%` / `%点.动作%` 取值。
  常见动作值有 `左键` / `右键`。
- 界面只读：点击不会拿走物品，也不会动玩家背包。同一玩家只保留最后打开的界面对象，
  重绘（切页、弹确认框）会顶掉旧的；关窗 / 退出 / 卸载 / 关服都会释放闭包。
- 按玩家的旧界面方法已移除，界面一律用「对象 + 闭包」。

## 9. 完整可运行示例：签到插件

把下面存成 `<gameDir>/nebula/签到/main.n`，带一个 `nebula.ini`，然后 `/nebula load 签到`：

```text
// 签到插件：/签到 领面包，背包面包超过 63 个时不再发。
[f]初始化
奖励物品:minecraft:bread
奖励数量:4
$世界.注册指令 签到 0 sign$

[f]加载
签到插件已加载

[指令]签到|sign
余:$世界.取物品数 %玩家名% %奖励物品%$
如果:%余%>63
    $世界.提示 %玩家名% "§7背包里的面包够多了，先吃掉再来吧"$
    返回
如果尾
$世界.给物品 %玩家名% %奖励物品% %奖励数量%$
$世界.音效 %玩家名% minecraft:entity.player.levelup$
$世界.提示 %玩家名% "§a签到成功 §7· §f面包 ×%奖励数量%"$
```

逐行看点：`[f]初始化` 每次编译都跑，所以注册指令写在这里；`[f]加载` 的提示只会在首次插入时出现；
`[指令]` 头列出规范名和别名；查询 `取物品数` 立即返回值可以赋给 `余`；给物品 / 音效 / 提示是动作，
排队落地；带空格的文案用引号包住；分支用裸 `返回` 提前结束。

> 这是演示插件，**没有做「每天一次」的持久化**。真要做每日限制，得把领取日期按玩家名存文件：
> 读取用 `$读文件 %库目录%/记录.json$`，改字段用 `$JSON键存$`，可用的文件写入函数见
> [`bridge/README.md`](../../bridge/README.md)。

## 10. 调试与排错

```text
/nebula list                 列出插件及调试开关
/nebula load <插件|--all>     加载；编译失败时其它插件不受影响
/nebula load <插件|--all>    加载；已加载则重编译（失败保留旧版本）
/nebula debug <插件|--all>    开启文件指纹监视，保存即重编译
/nebula undebug <插件|--all>  关闭
/nebula unload <插件|--all>   卸载（加载器按归属回收指令 / 界面 / 生物 / 事件订阅，并重推资源包）
```

插件没反应时按这个顺序查：

1. `/nebula list` 里是否已加载；编译失败的信息在服务端日志 / 控制台。
2. `$调用$` 的**结尾 `$` 有没有漏**——漏了整行会被当普通文本输出，看起来像「执行了但没效果」。
3. `如果尾` / `结束` 是否闭合，词条之间是否用了块外空行。
4. 一行是不是塞了两个 `$调用$`。
5. 在函数里读事件变量 / 配置 → 忘了显式传参（第 3 节）。
6. 动作后面立刻查询 → 读到的是旧值（第 5 节）。
7. 玩家目标传了 UUID 而不是名字（第 5 节）。
8. 方块查询对未加载区块返回空（第 5 节）。
9. 指令改名后旧入口还在 → 重启服务端。
10. 输出行没私聊化 → 被广播出去了，改用 `$世界.提示$`。

`python NebulaLoadMod/selftest/regress.py` 是**桥接层**的一键回归（隔离服 + 双假玩家 +
原版命令反查），不是插件单元测试；插件逻辑还是靠 `/nebula debug` + 游戏内验证。
