# 事件清单

> 事件系统让插件**响应**游戏里发生的事。宿主把 NeoForge 事件整理成 payload JSON 注入词库变量，
> 词库用 `[事件]名字` 词条接收。写法与排错见 [`plugin-guide.md`](../plugin-guide.md) 第 4、10 节。

宿主内置 6 个中文事件（下表），另有 8 个中文别名词条（7 个玩家交互 + 玩家退出，
见「中文交互事件」），另外通过**通用事件桥**把 NeoForge 事件总线上的 267 个事件类
按订阅对接给词库。

## 事件词条格式

```text
[事件]玩家聊天
如果:%消息%==你好
    $世界.提示 %玩家名% §a你好$
如果尾
```

- 头写 `[事件]名字`；正文顶格，缩进只用于 `如果` / `遍历` 块内部，块要闭合。
- payload 字段注入成 `%变量%`；玩家 / 实体 / 方块这类是 **JSON 对象**，用 `%变量.字段%` 取字段。
- 事件帧的父作用域是 `plugin.state`，能读到 `[f]初始化` 里赋的配置；但 `[函数]` 帧读不到，
  需要的变量要显式传参。

## 输出、取消与拦截

- 事件里的**裸文本行会被宿主广播 / 回给玩家**；只想让某个人看到，用
  `$世界.提示 %玩家名% 文本$`。
- 想拦截事件用 `$世界.取消事件$`：桥接层把取消标志写在本次事件槽位，宿主在分发结束后统一
  `setCanceled(true)`。**只有「可取消」列是「是」的事件有效**。
- payload 只含基础类型与 JSON，不跨线程持有 Minecraft 对象；别指望拿到 Java 对象。
- 事件异常不会抛到 NeoForge 总线，只记日志并跳过该插件。

## 玩家进入

`[事件]玩家进入` · 来源 `PlayerLoggedInEvent` · **可取消：否**

每次**连接成功**都会触发一次（包括断线重连），不是「首次进服」；首次进服要自己查账号库。

| 变量 | 类型 | 说明 |
| --- | --- | --- |
| `%玩家%` | `Object` | 玩家快照：`名称` / `uuid` / `维度` / `x` `y` `z` |
| `%玩家名%` | `String` | 玩家名，等价 `%玩家.名称%` |
| `%管理员%` | `String` | `是` / `否` |
| `%维度%` | `String` | 注册名，如 `minecraft:overworld` |

```text
[事件]玩家进入
$世界.提示 %玩家名% "§7你进服了，UUID %玩家.uuid%"
```

> 登录类插件必须在这个事件里**重建会话**：玩家上一局是「已登录」，关服 / 重载 / 重连后
> 必须重新输密码，否则杀一次进程再进服就能绕过验证。

## 玩家聊天

`[事件]玩家聊天` · 来源 `ServerChatEvent` · **可取消：是**

| 变量 | 类型 | 说明 |
| --- | --- | --- |
| `%玩家%` | `Object` | 玩家快照：`名称` / `uuid` / `类型` / `维度` / `x` `y` `z` / `血量` / `最大血量` / `模式` / `潜行` / `手持物品.名称` |
| `%玩家名%` | `String` | 玩家名，等价 `%玩家.名称%` |
| `%消息%` | `String` | 玩家原始发言文本（`getRawText()`） |
| `%管理员%` | `String` | `是` / `否`（文本），按 OP 列表判断 |
| `%潜行%` | `String` | `是` / `否`，是否按住潜行 |
| `%维度%` | `String` | 注册名，如 `minecraft:overworld` |
| `%x%` `%y%` `%z%` | `Integer` | 玩家坐标 |

示例：

```text
[事件]玩家聊天
如果:%消息%==帮助
    $世界.提示 %玩家名% "§e/商店 打开商店"$
    $世界.取消事件$
如果尾
```

> 注意：取消后这条消息所有人都看不到（相当于被吞掉），确认这是你要的效果。

## 实体受伤

`[事件]实体受伤` · 来源 `LivingDamageEvent.Post`（**伤害已结算**）· 可取消：否

| 变量 | 类型 | 说明 |
| --- | --- | --- |
| `%攻击者%` | `Object` | 伤害来源实体快照：`名称` / `uuid` / `维度` / `x` `y` `z` / `血量` / `最大血量` / `类型`；环境伤害无来源实体时为 `{}` |
| `%攻击者名%` | `String` | 来源实体名；无来源实体时填伤害类型 id（如 `fall` / `generic`） |
| `%实体%` | `Object` | 被伤害实体快照：`名称` / `id` / `类型` / `维度` / `x` `y` `z` / `血量` / `最大血量` |
| `%实体名%` | `String` | 目标名字（生物显示名或玩家名） |
| `%伤害%` | `Float` | 本次**实际**伤害（护甲 / 附魔 / 格挡已算完） |
| `%剩余%` | `Float` | 伤害生效后目标血量；死亡为 `0.0` |
| `%最大血量%` | `Float` | 目标最大血量 |
| `%身高%` | `Float` | 目标碰撞箱高度（`getBbHeight()`），飘字定位用 |
| `%暴击%` | `String` | `是` / `否`；仅玩家来源按原版 `Player#attack` 条件复算，其余恒 `否` |
| `%原因%` | `String` | 伤害类型 id，如 `player_attack` / `arrow` |
| `%致死%` | `String` | `是` / `否` |
| `%维度%` `%x%` `%y%` `%z%` | — | 目标所在位置 |

示例：

```text
[事件]实体受伤
伤害文:$数字格式化 %伤害% 1$
如果:%致死%==是
    $世界.动作栏 %攻击者名% "§c已击杀 §f%实体名%"$
    返回
如果尾
$世界.动作栏 %攻击者名% "§7对 §f%实体名% §7造成 §c%伤害文% §7点伤害"$
```

> 注意：**任何掉血都会转发**（只要 `伤害 > 0`），不限来源——玩家攻击、怪物互殴、弹射物、
> 摔落、岩浆、`/damage` 命令、玩家自伤都进词库。环境伤害没有来源实体，此时 `%攻击者%` 是 `{}`、
> `%攻击者名%` 是伤害类型 id、`%暴击%` 恒为 `否`；写词条时不要假定 `%攻击者.名称%` 一定有值。
> `%实体.血量%` 与 `%剩余%` 是同一个数。

## 实体治疗

`[事件]实体治疗` · 来源 `LivingHealEvent`（**回血写入之前**）· **可取消：否**

| 变量 | 类型 | 说明 |
| --- | --- | --- |
| `%实体%` | `Object` | 回血实体快照：`名称` / `id` / `类型` / `维度` / `x` `y` `z` / `血量` / `最大血量` |
| `%实体名%` | `String` | 实体名字 |
| `%数值%` | `Float` | 本次**真实**回复量（已按最大血量截断） |
| `%之前%` | `Float` | 回血前血量 |
| `%剩余%` | `Float` | 回血后血量 |
| `%最大血量%` | `Float` | 最大血量 |
| `%身高%` | `Float` | 碰撞箱高度，飘字定位用 |
| `%原因%` | `String` | `自然回复` / `效果` / `其它`（按再生效果、玩家饥饿值粗分） |
| `%满血%` | `String` | `是` / `否`，这次回复是否把血补满 |
| `%维度%` `%x%` `%y%` `%z%` | — | 实体所在位置 |

示例（飘一个绿色 +N，满血时什么都不发）：

```text
[事件]实体治疗
如果:%原因%==自然回复
    返回
如果尾
回:$数字格式化 %数值% 1$
飘y:[%y%+%身高%]
$世界.悬浮字 %维度% %x% %飘y% %z% "§a+%回%" 1.0 1.1 22$
```

> 注意：
> - **已经满血时宿主不会转发这个事件**——每次 `heal()` 都会被截断到 0，事件根本进不来，
>   词库不需要再判断一次。
> - 原版没有「谁治的」信息：自然回血（饥饿 / 饱和度）、生命恢复效果、药水都走同一个
>   `LivingEntity#heal`，`%原因%` 是宿主按「有没有再生效果 + 是否满饥饿玩家」粗分的。
>   饱和状态下自然回血是 **每 0.5 秒 +1**，想安静就把 `%原因%==自然回复` 的那一批过滤掉。

## 方块破坏

`[事件]方块破坏` · 来源 `BlockEvent.BreakEvent` · **可取消：是**

| 变量 | 类型 | 说明 |
| --- | --- | --- |
| `%玩家%` | `Object` | 玩家快照，含 `名称` / `uuid` / `模式` / `潜行` / `手持物品.名称` 等 |
| `%玩家名%` | `String` | 玩家名 |
| `%方块%` | `Object` | 方块快照：`名称`（注册名）/ `数据`（BlockState 文本）/ `维度` / `x` `y` `z` / `坐标` |
| `%坐标%` | `Object` | `x` / `y` / `z` 的坐标对象 |
| `%工具%` | `String` | 手持物品名称 |
| `%模式%` | `String` | 游戏模式（中文标签） |
| `%管理员%` `%潜行%` | `String` | `是` / `否` |
| `%维度%` | `String` | 注册名 |
| `%x%` `%y%` `%z%` | `Integer` | 方块坐标 |

示例（连锁砍树用的就是这些字段）：

```text
[事件]方块破坏
树种:$取树种 %方块.名称%$
如果:$文本长度 %树种%$==0
    返回
如果尾
$世界.提示 %玩家.名称% "§7砍到 §f%方块.名称%"$
```

> 注意：`%方块.名称%` 是注册名（如 `minecraft:oak_log`），不是显示名。

## 每秒

`[事件]每秒` · 来源 `ServerTickEvent.Post`（每 20 tick 一次）· **可取消：否**

给「没有平台事件」的逻辑用：登录倒计时、超时踢人、定时检查。没有插件写 `[事件]每秒` 时
这一次分发只是空转，开销可以忽略。

| 变量 | 类型 | 说明 |
| --- | --- | --- |
| `%服务器tick%` | `Integer` | 服务器启动以来的 tick 数（`Long`，约 20/秒） |
| `%在线人数%` | `Integer` | 当前在线玩家数 |

示例（维护一个 300 秒未登录就踢出的倒计时，节选自 `server-1.21.11/nebula/登录/main.n`）：

```text
[事件]每秒
表:$世界.取玩家列表$
遍历:i,人=%表%
    名:%人.名称%
    剩:[%会话.截止%-%今%]
    如果:%剩%<=0
        $世界.踢出玩家 %名% "§c验证超时"$
    如果尾
结束
```

> - 一秒钟只跑一次，**不是**每 tick；按 20 tick 计数，TPS 掉到 10 时它就是 2 秒一次。
> - 需要「严格按墙钟计时」就用 `$当前时间戳$` 存截止时间再比较，别累加计数器。
> - 这个事件每秒都会进词库，别在这里做全量文件扫描或长 IO。

## 中文交互事件

玩家左右键交互这一类最常用，宿主给整组 `PlayerInteractEvent` 配了**中文词条名**和
**中文 payload 键**（玩家退出也顺带中文化），词库里不必再写 Java 类名，
也不用 `%entity.name%` 这种英文变量。
中文名写在 `nebula/events.json` 顶层的 `cnNames`（由 `tools/gen_events.py` 随清单生成），
`EventBridge` 按别名找到事件类、动态注册监听器，分发时用的仍是这个中文词条名。

| 词条 | 对应事件类 | 触发时机 |
| --- | --- | --- |
| `[事件]右键物品` | `PlayerInteractEvent.RightClickItem` | 只由 `useItem` 触发（客户端没命中方块）；**对着方块右键不会进来** |
| `[事件]右键方块` | `PlayerInteractEvent.RightClickBlock` | 右键点到方块 |
| `[事件]右键空气` | `PlayerInteractEvent.RightClickEmpty` | 右键没命中方块 / 实体 |
| `[事件]左键方块` | `PlayerInteractEvent.LeftClickBlock` | 左键点到方块 |
| `[事件]左键空气` | `PlayerInteractEvent.LeftClickEmpty` | 左键没命中方块 |
| `[事件]右键实体` | `PlayerInteractEvent.EntityInteract` | 右键点到实体 |
| `[事件]右键实体部位` | `PlayerInteractEvent.EntityInteractSpecific` | 右键点到实体的具体部位 |

玩家退出不属于交互，但同样给了中文名：`[事件]玩家退出` →
`PlayerEvent.PlayerLoggedOutEvent`（侧边栏插件用它撤掉离线玩家的行），变量与其它
玩家类事件一致（`%玩家名%` / `%维度%` / `%x%` `%y%` `%z%`）。

**中文 payload 变量**（英文键一律保留，旧插件照常能跑）：

| 变量 | 含义 | 出现条件 |
| --- | --- | --- |
| `%玩家名%` / `%玩家%` | 玩家名 / 玩家快照（`.名字%` `.类型%` `.维度%` `.编号%` `.x%` `.y%` `.z%`） | 全部 |
| `%维度%` / `%x%` `%y%` `%z%` | 玩家所在维度与坐标 | 全部 |
| `%物品%` / `%数量%` | 手持物品 id（空手为空串）/ 数量 | 事件有 `getItemStack()` 时 |
| `%手%` / `%主手%` | 主手 / 副手；是 / 否 | 事件有 `getHand()` 时 |
| `%方块x%` `%方块y%` `%方块z%` / `%坐标%` | 点到方块的坐标 / `{x,y,z}` | 右键方块 / 左键方块 |
| `%面%` / `%面英文%` | 上 下 北 南 东 西 / 原版 `UP DOWN …` | 右键方块 / 左键方块 |
| `%用物品%` / `%用方块%` / `%动作%` | 允许 拒绝 默认 跳过 / 开始 中止 停止 持续 | 对应 getter 存在时 |
| `%目标%` / `%目标名%` | 被右键实体的中文快照 / 名字 | 右键实体系列 |
| `%事件名%` / `%原事件名%` / `%事件类%` | 中文名 / 清单简名 / 完整类名 | 全部 |

其余事件类仍用英文简名订阅，但只要 payload 里有 `entity` / `itemStack` / `pos`，
也会同时补一份中文键（`%实体%`、`%实体名%`、`%物品%`、`%方块x%` …）。

```text
[事件]右键物品
人:%玩家名%
物:%物品%
如果:%主手%==是
    $世界.提示 %人% 你用 %手% 拿着 %物%$
如果尾
```

注意：

- **`右键物品` 不是「右键任何东西」**：1.21.11 里「看着方块右键」走 `ServerPlayerGameMode.useItemOn`
  → 只发 `RightClickBlock`；`RightClickItem` 只在客户端没命中方块、发 `ServerboundUseItemPacket` 时由
  `useItem` → `CommonHooks.onItemRightClick` 发出。凡是要「点到的方块坐标 / 面」（刷怪蛋、放置类），
  一律挂 `[事件]右键方块`；挂错的表现是「点方块不触发、点空气触发了又没方块可生成」。
- 写中文名**必须用带 `cnNames` 的新 jar**；旧 jar 会把中文名当成「查不到清单」直接跳过，
  事件静默不触发。英文词条名在两个版本都有效，可以平滑过渡。
- 同一个插件别同时写 `[事件]右键物品` 和 `[事件]PlayerInteractEvent.RightClickItem`，
  否则一次交互会注册两个监听器、分发两遍。
- 事件帧里能用 `%玩家名%` 这类顶层键；要传给 `[函数]` 就先赋给简单变量再传
  （用户函数实参不展开点号字段）。
- 值与原版命令相关的部分保持原样：物品 id 仍是 `minecraft:diamond_sword`，
  `%面英文%` 仍是 `UP`；中文值只用于词库里的比较与提示。

## 指令与界面事件

除了上面 6 个内置事件和 8 个中文别名词条，还有两类**宿主主动分发**的入口，写法见
[`指令与界面.md`](指令与界面.md) 与 [`plugin-guide.md`](../plugin-guide.md) 第 6、8 节：

| 入口 | 触发 | 主要变量 |
| --- | --- | --- |
| `[指令]规范名\|别名` | 玩家 / 控制台执行插件自注册的指令 | `%玩家%` / `%玩家名%` / `%指令%` / `%参数%` / `%管理员%` |
| 界面点击闭包 | 玩家点击词库打开的箱子界面 | payload JSON 落在闭包的 `%参数1%`：`槽位` / `动作` / `按钮` / `物品` / `数量` / `区域` 等 |

## 避开误区

- **动作延迟执行**：事件里 `$世界.设方块 …$` 后立刻 `$世界.取方块 …$` 读到旧值。要验证就换一次
  事件触发，或用宿主的查询接口。
- 别在高频事件里做长 IO 或全量词库扫描；词库事件是同步跑在服务端主线程的。
- 别在事件里用 `$世界.执行命令 say …$` 拼超长文本（chat 上限 256 字符）。
- 玩家目标统一用**名字**，不要用 UUID（`give` / `effect` 会拒绝 UUID 字面量）。
- 事件输出行会广播，私聊务必用 `$世界.提示$`。

## 通用事件桥（NeoForge 全量事件）

除了上面的内置中文事件，宿主还能把 **NeoForge 事件总线上的任意事件类**直接对接给词库。
jar 内的 `nebula/events.json` 是构建期从 `neoforge-21.11.42-universal.jar` 抽取的清单
（当前 267 个事件类，含 `Pre` / `Post` 等内部类），由 `NebulaLoadMod/tools/gen_events.py` 生成。
清单顶层的 `cnNames` 同时给出 8 个中文别名（`右键物品` → `PlayerInteractEvent.RightClickItem`、
`玩家退出` → `PlayerEvent.PlayerLoggedOutEvent` 等），详见上面的「中文交互事件」；
别名随清单一起生成，升级 NeoForge 不会丢。

词条头直接写 **Java 事件类简名**，内部类用点号代替 `$`：

```text
[事件]EntityJoinLevelEvent
$世界.广播 %entity.name% 加入了 %entity.dimension%$
```

- **按订阅注册**：宿主在开服 `loadAll` 后、以及 `/nebula load|unload|debug|undebug`
  之后读一次订阅表，只给词库真正写了词条的事件挂监听器。没订阅就一个额外监听器都没有，
  也不会多跨一次 JNI。订阅表来自 Rust 侧 `eventTriggers(handle)`。
- **payload 用 Java 字段名**：反射遍历事件的 public getter，`getEntity()` → `%entity%`、
  `getPos()` → `%pos%`、`isCanceled()` → `%canceled%`，另有 `%eventClass%`（完整类名）。
  复杂对象转成 JSON：`Entity` → `{name,id,type,dimension,x,y,z}`，`BlockPos` → `{x,y,z}`，
  `ItemStack` → `{item,count}`，`Identifier` / `Component` / `UUID` / 枚举 → 字符串；
  集合最多 32 项，未知对象只留 200 字符以内的短字符串。**payload 里没有 Java 对象引用**。
  英文键之外还会补一份中文别名（`%玩家名%` / `%物品%` / `%面%` / `%事件名%` …），
  值里的枚举也翻成中文（主手 / 副手、上 / 下 / 北 …），完整对照见「中文交互事件」。
- **可取消**：事件实现 `ICancellableEvent` 时，`$世界.取消事件$` 会真的 `setCanceled(true)`；
  否则无效（与内置事件口径一致）。
- **高频节流**：`EntityTickEvent.*` / `PlayerTickEvent.*` / `LevelTickEvent.*` /
  `ServerTickEvent.*` 每实体 / 每维度每 tick 都触发，宿主按 **20 tick（1 秒）** 节流后
  才分发。别指望逐帧精度；真要逐帧请下沉到宿主 Java 侧（如 `FloatingText.tick`）。
- **加载期事件收不到**：`RegisterCommandsEvent`、`BuildCreativeModeTabContentsEvent` 这类
  在 mod 加载阶段就发完了，专用服运行时订阅也收不到，宿主会记一条 WARN。客户端专用事件类
  在服务端不存在，注册时跳过。清单中的辅助枚举 / 接口 / 抽象基类也会被运行时过滤。
- **内置事件不重复**：`玩家聊天` / `实体受伤` / `实体治疗` / `方块破坏` / `玩家进入` /
  `每秒` 这 6 个中文名由宿主手写 handler 分发；`右键物品` / `玩家退出` 等 8 个中文名
  走 `cnNames` 别名表解析到清单条目，两类都不会被重复注册。英文词条名与中文别名等价，
  二选一即可。
- 升级 MC / NeoForge 版本后要重跑 `python NebulaLoadMod/tools/gen_events.py` 再全量构建；
  `regress.py` 会按内容比对 jar 内清单，滞后就报「产物与源码不一致」。

清单本身是构建期快照，不是运行时反射扫 classpath；想看某个版本有哪些可订阅事件，
直接查 `NebulaLoadMod/src/main/resources/nebula/events.json`。

真机验证：`regress.py` 的自检词库订阅了 `[事件]EntityJoinLevelEvent`，开服后宿主动态注册该
监听器，假玩家进服时收到 `%eventClass%` / `%entity.name%` 并写进日志（28/28 PASS 里的
「通用事件桥动态注册」一项）。改词库后 `/nebula load <插件>` 会重编译并刷新订阅表，无需重启。

## 调试

```text
/nebula list                    确认插件已加载
/nebula debug <插件>            改 .n 即自动重编译
/nebula undebug <插件>          关闭
```

触发事件没反应时，先在事件第一行放一个 `$世界.提示 %玩家名% 事件到了$`，确认是不是根本没分发；
再逐行排查 `$调用$` 结尾的 `$`、块闭合与变量名。完整排错清单见
[`plugin-guide.md`](../plugin-guide.md) 第 10 节。
