# 指令与界面 API

> 手写维护，无生成脚本。对应 LLSE 分组：GameAPI / Command / GuiAPI。
> 签名里 `[ ]` 是可选参数；参数格式、返回值类型与调试方式见 [`README.md`](README.md)。
> **查询立即返回、动作延迟执行**；查询失败返回空串 / `{}` / `[]` / `0`，动作失败记 WARN。

### 取物品数

`$世界.取物品数 玩家 物品$`

- 参数：
  - 玩家 : `String`；传玩家名或玩家 JSON 对象（自动取 `名称`），不要传 UUID
  - 物品 : `String`
- 返回值：查询结果（可赋值给变量）
- 返回值类型：`String` / `Object`
- 失败回退：查询失败返回空串 / `{}` / `[]`
- 实现：遍历 `Inventory#items / armor / offhand` 的 `ItemStack#getCount`，返回总数

示例：

```text
余:$世界.取物品数 %玩家名% minecraft:dirt$
$世界.提示 %玩家名% "§7余额：%余% 个泥土"
```


### 注册指令

`$世界.注册指令 规范名 [权限] 别名… [参数=值,值…]$`

- 参数：
  - 规范名 : `String`
  - 权限 : `String`（可选参数，省略时用宿主默认值）
  - 别名… : `String`
  - 参数= : `String`（可选，**必须写在最后**；逗号分隔，支持 `,` `，` `、` `|`）
- 返回值：空串（动作排队执行）
- 返回值类型：`Null`
- 失败回退：动作失败返回空串并记 WARN
- 实现：`CommandDispatcher#register`；重复注册按插件 + 规范名幂等，权限或子参数变化拆旧节点重注册
- 子参数：每个值注册成一个 literal 子节点，**只为客户端 Tab 补全与提示**；
  玩家点到它时把该值原样当 `%参数%` 送给词库（其后仍可跟任意文本），所以
  `如果:%参%==帮助` 这类判断不用改。不写 `参数=` 时退化成「后面什么都能输」的贪婪参数。

示例：

```text
$世界.注册指令 商店 0 shop 泥土商店 参数=帮助,余额$
```

```text
[指令]商店|shop|泥土商店
参:$去除左右 %参数%$
如果:%参%==帮助
    $世界.提示 %玩家名% "§e/商店 §7开店，§f/商店 余额 §7查余额"$
    返回
如果尾
```

> 注意：`参数=` 只影响**输入体验**（Tab 里能看见 `帮助` / `余额`），不拦截别的写法：
> 玩家硬打 `/商店 随便写` 照样走贪婪参数进 `[指令]`，由词库自己判断。

> 注意：动作**延迟执行**：同一词条里紧接着查询会读到旧值，要到下一次事件 / 重编译 才生效。

> 注意：写在 `[f]初始化`（每次编译都跑，宿主去重）。**不再需要写 `[f]卸载` 注销**：
> 加载器每次编译按「批次 + 插件归属」对账，本批没声明的入口自动下线；`/nebula unload`
> 时直接按插件整批注销。改掉 / 删掉旧名字后下次编译就生效，不用重启。

### 弹窗输入

`$世界.弹窗输入 玩家 标题 提示 标签 最长 提交指令 [退出指令]$`

- 参数：
  - 玩家 : `String`；传玩家名或玩家 JSON 对象（自动取 `名称`）
  - 标题 : `String`，支持 `§` 颜色码（宿主解析成组件样式）
  - 提示 : `String`，弹窗正文，支持 `§` 颜色码；倒计时、剩余次数这类动态提示由词库拼进这里
  - 标签 : `String`，输入框左侧标签
  - 最长 : `Int`，输入框 `max_length`（1~256）
  - 提交指令 : `String`，已注册的指令名，**不带** `/`；宿主补上 ` $(pw)` 模板
  - [退出指令] : `String`，可选尾参，默认空。非空时在提交按钮**左侧**加一个「退出服务器」按钮，点它执行该指令（不带参数）；通常配合词库里注册的指令调 `踢出玩家`，给未登录玩家一个明确出口
- 返回值：空串（动作排队执行）
- 返回值类型：`Null`
- 失败回退：玩家不存在 / 提交指令为空 / 提交模板解析失败时不下发，不记异常；退出指令模板解析失败只退回单按钮弹窗，**不会连弹窗一起丢**
- 实现：`退出指令` 为空用 `Holder.direct(NoticeDialog)`（单按钮）；非空改用 `MultiActionDialog`，按钮列表顺序即从左到右，`columns=2` 排成一行。`canCloseWithEscape=false`，`after_action=close`；提交按钮挂 `dynamic/run_command`，客户端把输入值替换到 `$(pw)` 后把整条命令发给服务端

> **退出指令必须能被解析成宏**：原版 `ParsedTemplate` 的 CODEC 只接受「至少含一个 `$(变量)`」的模板，纯文本 `nquit` 会报 `No variables in macro`。宿主在退出指令不含 `$(` 时自动补 ` $(pw)`，所以点「退出服务器」实际发出的是 `nquit <输入值>`——指令自己忽略这个多余参数即可。早期版本直接把纯文本丢进去，解析失败后整个弹窗都不下发，表现就是「玩家进服完全没有弹窗」。

> **提交会关闭弹窗**：`after_action=close` 决定每次提交后弹窗都消失。登录类词库必须在所有校验失败的分支重新调一次 `弹窗输入`，否则玩家会「输错一次密码，输入框就没了」。
>
> 这是 1.21.6 起才有的服务端可下发表单组件，低于 1.21.6 的版本不支持（当前 1.21.11 可用）。命令模板里的值会被引擎转义特殊字符，登录插件这类纯数字密码最稳妥。

示例（登录插件的真实写法，提示文本里不含空格，避免被按空格切成多个参数）：

```text
$世界.弹窗输入 %玩家名% §8[§b星云§8]§f输入密码 §7请输入4-8位数字密码§8·§f剩300秒§8·§7错误0/5次 密码 8 npw nquit$
```

提交后客户端执行 `npw <输入值>`，词库在 `[指令]npw` 里收到完整密码；点左侧按钮执行 `nquit <输入值>`（退出指令不需要这个值，忽略参数即可）。
