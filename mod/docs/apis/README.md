# `世界` API 参考 · 写在前面

> 本套文档的体例参考 [LegacyScriptEngine 的 API 文档](https://docs.levimc.org/LegacyScriptEngine/zh/apis/)：
> 先约定数据类型与描述格式，再按类别分篇，每条 API 用「用途 → 签名 → 参数 → 返回值 → 示例 → 提示」的固定格式。
> 对应到我们这里，LLSE 的 `mc` / `Player` 那套对象换成了词库的 `$世界.方法 …$` 与 `%变量%`。

## ⛳ 放在前面

星云词库引擎把 Minecraft Java 版服务端的能力封装成 `世界` 注入类，词库里用 `$世界.方法 参数…$` 调用。Java 宿主只做事件转发与动作落地，
**业务逻辑全部写在 `.n` 词库里**。

还不会写插件？先看 [`plugin-guide.md`](../plugin-guide.md)。这里只查 API。

## 💊 数据类型

词库是弱类型的，所有值最终都是**文本**或 **JSON 文本**。下面这些类型名只出现在 API 文档的参数
与返回值说明里，用来告诉你该传什么、会拿回什么。

| 文档类型 | 词库里的写法 | 说明 |
| --- | --- | --- |
| `String` | 一段文本，如 `minecraft:stone` | 注册名、名字、文本。含空格要加引号 `"§7余额：%余%"` |
| `Integer` | `64`、`3` | 整数（坐标、数量、槽位、等级） |
| `Float` | `0.6`、`1.5` | 小数（音量、音调、部分数值） |
| `Boolean` | `是` / `否` | `是 / true / 1 / 开 / 真 / yes / on` 都视为真 |
| `Text` | 剩余的一串文本 | **吞掉该位次之后的全部实参**，用空格拼接，通常是最后一个参数 |
| `Object` | JSON 文本，如 `{"名称":"Steve"}` | 用 `%变量.字段%` 取字段，如 `%玩家.名称%` |
| `Array` | JSON 数组文本 | 配合 `遍历:i,件=%表%` 使用 |
| `Function` | `回调:[函数] … 结束` | 函数值；宿主回调时 payload 落在 `%参数1%` |
| `Null` | 空串 | 查询失败或动作无返回 |

几个常见的**对象型参数**（都是 JSON 或能自动转成的形式）：

- `玩家` — 传玩家名最稳；也可以传 `%玩家%` 这种 JSON 对象（宿主自动取 `名称`）。
  **别传 `%玩家.uuid%`**：`give` / `effect` 等命令在 1.21.1 会拒绝 UUID 字面量。
- `维度` — 注册名，如 `minecraft:overworld` / `minecraft:the_nether`。
- `实体` — 数字 id / UUID / 名称，宿主统一换成选择器。
- `面` — `$世界.创建界面$` 返回的界面对象 id。
- `坐标 / 方块 / 玩家状态 / 实体数据` — 查询返回的 JSON 对象，用 `%变量.字段%` 取字段。

> `%时间%`（本地时间）和 `%版本%`（引擎版本）是**引擎内置系统变量**，词库里给同名变量赋值会被
> 遮蔽。自己的变量加前缀，如 `%SC时刻%`。

## 📌 API 文档描述约定

后面每一条 API 都按同一个格式写，看一条就会看全部：

**1. 签名**

```text
$世界.取方块 维度 X Y Z$
$世界.取实体列表 [维度] [上限]$
```

参数按**位次**用空格分隔；`[ ]` 框起来的是**可选参数**，省略时用文档里给出的默认值。
签名里的 `$` 必须成对——**结尾的 `$` 漏掉，整行会被当普通文本输出**。

**2. 参数**

按 `参数名 : 类型` 逐项列出，并写明含义与默认值。`Text` 类型会吞掉后面的全部实参。

**3. 返回值 / 返回值类型**

- **查询类**（`取…` / `获取…` / `玩家有标签` 等）：调用时**立即返回**结果，可以赋值
  `余:$世界.取物品数 %玩家名% minecraft:dirt$`。
- **动作类**：返回空串（`Null`），实际效果**排队延后执行**——同一词条里
  `$世界.设方块 …$` 之后立刻 `$世界.取方块 …$` 读到的仍是旧值，要到下一次事件 / reload 才生效。
- 查询失败返回空串 / `{}` / `[]` / `0`（每条 API 会注明），动作失败返回空串并在服务端日志记 WARN。

**4. 实现 / 状态**

给出宿主侧落地方式（原版命令、稳定 API 或反射兜底）与已知降级，便于排查「为什么这个读不到」。

**5. 示例与提示**

示例是真实词库写法；`注意` / `警告` / `提示` 只写会踩坑的点。

## 📡 调试

```text
/nebula list                 列出插件及调试状态
/nebula load|reload <插件>    加载 / 重编译（失败保留旧版本）
/nebula debug|undebug <插件>  开关文件指纹自动重编译
/nebula unload <插件>         卸载并释放界面闭包
```

没有 LLSE 那种 `jsdebug` 交互控制台；验证词库靠 `/nebula debug` + 游戏内触发事件，
或用 `$世界.执行命令 say …$` 把中间值打出来（注意 256 字符上限）。
桥接层的一键回归是 `python mod/selftest/regress.py`（隔离服 + 双假玩家 + 原版命令反查）。
