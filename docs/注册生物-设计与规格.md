# `$世界.注册生物` 实现与规格

> 状态：**已落地，模组 0.4.0**（MC 1.21.11 / NeoForge 21.11.42）。
> 目标：把「注册物品」与「生物」整合成**一个生物对象**，词库用对象方法逐项设数据；宿主一次派生全部产物。
> 已验证：`cargo test --lib` **11/11**、隔离服回归 **30/30 PASS / 0 告警**、真机动态加载卸载往返通过。
> 落点：本文在仓库根 `docs/`，**不进** `NebulaLoadMod/docs/`（那里所有 `.md`/`.html` 会被打进 jar 并做 SHA256 指纹，新增文件会让 `--verify-only` FAIL）。

---

## 1. 为什么是对象

词库引擎（`rust-nebula/crates/nebula`）原生支持有状态实例，这套 API 直接用它，而不是自造 JSON 协议：

| 能力 | 证据 |
|---|---|
| 调实例方法 | `$ZIP对象.写 %源%$`、`$图.绘制圆形 …$`（`assets/lib/*.n`） |
| 原生方法拿到「自己」 | `d.v.scope.self_class()` → `Arc<ClassInstance>`（`builtins/zip.rs`） |
| 实例存字段 | `inst.local_value.set/get` |
| 返回类实例 | `Value::Class(Arc<DicClass>)`（`builtins/cmd.rs` 等十余处） |
| 读字段 | `%怪.血量%`（`template.rs:377` 遇 `Value::Class` 取 `local_value`） |
| 普通赋值保真 | `runs_val_typed` 的 `Ok(other) => put_var_typed`，对象不会被转成字符串 |
| 方法分派 | `interp.rs:2623` `Some(Value::Class(c)) => run_class_method`，不依赖 `class_name` |

桥接层里 `NValue` 就是 `Value` 的别名，`注册生物` hook 直接返回 `NValue::Class`。

## 2. 硬约束（决定了实现形态）

1. **注册表是两端握手时比对的静态契约**。服务端单方面新增 `EntityType`，客户端走
   `neoforge.network.registries.sync.server-with-unknown-keys` 断开。`unfreeze` 虽有，
   但客户端拿到词库定义的唯一通道是进服才推的资源包，来不及参与注册。
   → **预置槽位池**：编译期注册 N 个通用 `EntityType<DynamicMob>`，运行期词库认领槽位绑定品种数据。
   **动态的是数据，不是注册项。**
2. **碰撞箱 / 眼高 / `MobCategory` 是 `EntityType.Builder` 编译期常量** → 槽位按体型档分组
   （`tiny 0.5²` / `small 0.9²` / `normal 0.6×1.8` / `large 1.5×2.0`，各 8 个，共 32）。
   属性在 spawn 后 `getAttribute(...).setBaseValue(...)` 覆盖。
3. **资源包在 `loadAll()` 之前打包**，`push()` 只在进服发 → 动态定义必须热重建 + 在线重推。
4. **创造页两份**：服务端 `BuildCreativeModeTabContentsEvent`（MOD 总线、启动期）+ 客户端
   `tryRebuildTabContents` 本地重建（读资源包 `assets/nebula/creative/*.json`）。

## 3. API

### 3.1 创建与提交

```
怪:$世界.注册生物 nebula:chest_creature$
$怪.设 名称 箱子生物$
$怪.设 体型 small$
$怪.设 血量 20$
$怪.设 容器格数 27$
$怪.外观 方块 nebula_bridge:mob_body_0 nebula_bridge:block/chest_creature -0.5 0 -0.5 0.45$
$怪.加物品 刷怪蛋 minecraft:clay_ball chest_mob_egg 箱子生物蛋 nebula:item/chest_mob_egg nebula:item/chest_mob_egg 16 生成蛋$
$怪.生效$
```

- `注册生物 品种` 返回 **`Value::Class` 生物对象**；同一插件同一轮重复调用幂等复用。
- `设` / `外观` / `造型` / `贴图` / `加物品` **只改对象字段，不发动作**；`生效` 才把快照打包成一条 `注册生物` 动作。
- 忘写 `生效` 不会静默失败：`apply_op` / `load_all` 结束时扫描本轮未提交对象，自动补提交并打 WARN。
- 偏移拆成 3 个数字实参（`[ ]` 会触发词库模板解析）；基底写全名。
- 所有方法返回空串，不会把返回值打进日志。

### 3.2 字段（`$怪.设 键 值$` 写，`%怪.键%` 读）

| 键 | 默认 | 校验 |
|---|---|---|
| `品种` | 创建时给定 | 只读 |
| `名称` | = 品种 | — |
| `体型` | `normal` | `tiny`/`small`/`normal`/`large` |
| `分类` | `creature` | 仅提示 |
| `持久` / `死亡掉落` | `是` | `是`/`否` |
| `血量`/`速度`/`跳跃`/`击退` | 20 / 0.22 / 0.42 / 0.4 | 数字 |
| `容器格数` | 0 | 0..54 |
| `容器距离` | 8 | 数字，钳到 1..64；玩家交互距离（0.6.6 起真正生效） |
| `碰撞箱` | 空 | `自动` 或 `宽,高`；空 = 用体型档注册尺寸（0.8.0） |
| `行为` | 空 | 预留，宿主暂未读取 |

非法值写进 `%报错%`（不打断编译），可用 `$!怪.设 …$` 捕获。

### 3.3 方法

| 方法 | 参数 | 作用 |
|---|---|---|
| `设` | 键 值 | 写字段 + 校验 |
| `外观` | 方式 方块模型 贴图 [偏移x y z] [阴影] | 派生 blockstate / 模型 / 客户端声明。第 2 参 `方块模型` 由槽位覆盖（写错只 WARN） |
| `造型` | 体\|盖 fromx fromy fromz tox toy toz | 覆盖体 / 盖盒子（1/16 格坐标 0..16，可小数）；只影响渲染，缺省即箱子形 |
| `贴图` | 体\|盖 面 u0 v0 u1 v1 [材质名] | 逐面覆盖 UV（面 = 北/南/东/西/上/下/全部，-32..32）；第 7 参指定材质 |
| `材质` | 名字 贴图 | 注册额外贴图，供 `贴图` 按面引用（编成 `t0`/`t1`…，须 ASCII） |
| `目标` | 类型 [对象] [数值1] [数值2] | AI 目标：注视/攻击/逃跑/恐慌/漂浮，装配原版 Goal（0.9.0） |
| `交互` | 开容器\|无\|给予 物品 数量 | 右键行为；`给予` 带 10 tick 冷却（0.9.0） |
| `掉落` | 物品 [概率] [数量] | 死亡额外掉落，与 `死亡掉落` 字段互不影响（0.9.0） |
| `加物品` | 用途 基底 标记 名称 [模型] [贴图] [堆叠] [创造页] [颜色] | 追加物品；`用途=刷怪蛋` 登记 `标记→品种`；`贴图` 优先于 `模型` 推导 |
| `生效` | — | 提交快照（幂等） |
| `卸载` | — | 单品种即时下线（可选，宿主会自动收口） |
| `列表` | [上限] | 该品种已生成实体（JSON 数组，字段 `uuid/品种/维度/x/y/z`） |

`世界` 方法表 137 → **138**（只加 1 条工厂），`world-specs.json` 未改。

## 4. 动态加载卸载

### 4.1 按批次整体替换

对象自带 `plugin` 归属，不需要跨语言 `声明` 字段：

1. 每次 `apply_op` / `load_all` 的 `actions` 是一批完整声明；动作带 `"插件"` 和 `"批次"`。
2. `MobRegistry.commit(batch)` 按插件收口：本批出现的覆盖/新增，**该插件名下未在本批出现的自动下线**。
3. 删掉一行 `$世界.注册生物$` 不需要写注销 —— `mob_retain()` 清旧代次时会逐个补发 `注销生物`。
4. `unload` 时该插件批次为空 → 全部下线；已生成实体保留（见 4.4）。
5. 编译失败：Rust 按 `失败插件` 丢弃该轮动作，旧对象集不动；`--all` 部分失败只丢失败插件的。

### 4.2 资源热更新

`MobSync.sync(server)` → `NebulaPack.rebuildAndRepush()`：全量重打 zip、重算 sha1，变了才遍历在线玩家重推。
全量重打是撤销条目的关键 —— `MobRegistry` 里没有该品种，重打后旧条目自然消失。
客户端 `ClientDecls` 缓存刷新周期从 100 tick 缩到 20 tick（1 秒），兜住热更后的观感。

### 4.3 三条编译路径

| 路径 | 入口 | 处理 |
|---|---|---|
| 开服 | `load_all()` | `markReady` + `commit(batch)` + `MobSync.sync` |
| 指令 | `/nebula load\|unload` → `apply_op()` | `executeActions` + `commit(batch)` + `MobSync.sync` |
| 调试自动重编译 | `refresh_debug_plugin()` → `dispatch_event()` | 返回里带 `批次`，`EventBridge.onEvent` 做 commit + sync |

### 4.4 卸载后已生成的实体

实体不消失、容器物品原样保留、定义下线后降级为「无外观 / 默认属性 / 容器仍可打开」；
`NebulaSpecies` / `NebulaSlots` 持久化在实体 NBT 里，重新 `load` 后同品种复用槽位，属性自动恢复。

## 8. 已知限制

1. **破坏性版本**：`nebula_bridge:chest_creature` 已删除，旧存档里的该实体读档会变未知实体。
   已 bump `mods.toml` 0.3.8 → **0.4.0**；两端 jar 必须同步（registry sync 会踢不同版本）。
2. **槽位上限 32**（4 档 × 8）。耗尽时报 `NEB` 诊断并跳过，不隐式复用。
3. **创造页运行期重建未真机实测**：资源包已热更，但客户端是否立刻重建创造页要实测；最坏需重开创造界面。
4. **`spawnEgg` 真玩家右键未实测**：品种解析路径已走通（`MobRegistry.speciesOf` → 槽位 → `mob.bind`），
   静态验证用 `summon` + `data merge` 覆盖了同一套 `applyDefinition`。
5. **`Entity#refreshDimensions` 未 `javap` 实证**：当前运行期不改碰撞箱（按档预设），所以影响小；
   将来要做「一个槽位多档位」必须先实证。
6. 客户端外观刷新有 ≤1 秒延迟（20 tick 缓存）。
7. 旧插件 `资源/物品列表|物品模型|方块状态|方块模型|客户端|创造物品.json` 已删除，
   若其它插件还在写这些目录，它们仍会走原有静态通道（与派生条目同名时派生优先）。
