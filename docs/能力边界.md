# 能力边界：词库接管到哪一步了

> 本文回答一个问题：**改一个生物/物品/玩法，什么时候只动词库，什么时候必须改 Java？**
> 与 `docs/注册生物-设计与规格.md`（实现规格）互补：那份讲"怎么做"，这份讲"边界在哪"。
> 最后核对版本：0.9.0（2026-11-16）

## 三层划分

| 层 | 谁实现 | 判断标准 |
|---|---|---|
| **声明层** | 词库 `main.n` | 只是"填参数"就能表达 → 宿主必须收进对象方法 / `世界` 方法 |
| **原语层** | mod（Java/Rust） | 需要引擎能力（寻路、注册表、渲染、网络）→ 只暴露一个原语，判断留给词库 |
| **硬边界** | mod | Minecraft 启动期就定死、运行期改不了 → 只能编译期注册 |

判断口诀：**「这只怪做什么」归词库，「世界允许什么」归引擎。**

## 一、已由词库完全接管

### 1.1 生物（`$世界.注册生物` + 对象方法）

| 维度 | 可声明项 |
|---|---|
| 身份 | 品种 id、名称（含语言文件派生）、体型档（决定槽位池） |
| 属性 | 血量 / 速度 / 跳跃 / 击退抗性 |
| 容器 | 格数（0 = 非容器）、交互距离、死亡掉落、持久 |
| 体积 | 碰撞箱：`自动`（按造型并集）或手写 `宽,高` |
| 外观 | 主贴图、额外材质（多张贴图）、体/盖盒子几何、逐面 UV、偏移、阴影 |
| 动画 | 弹跳 / 前倾 / 开盖 / 开合 / 摇摆 / 缩放 / 旋转 / 浮空（8 个量，前 7 个纯客户端） |
| AI | 注视 / 攻击 / 逃跑 / 恐慌 / 漂浮（装配原版 Goal） |
| 交互 | 右键行为：开容器 / 无（交还事件）/ 给予物品（10 tick 冷却） |
| 掉落 | 死亡额外掉落：物品 + 概率 + 数量（与容器内容的「死亡掉落」独立） |
| 蛋 | 用途=刷怪蛋时自动变真 `SpawnEggItem`；标记、名称、模型、贴图、堆叠、创造页、颜色 |
| 行为 | `[事件]` 驱动 + `$世界.巡逻$`（一行默认策略）或四个原语自拼 |

派生出来的一切（blockstate、模型 JSON、客户端声明、语言、创造页、物品 definition）都由宿主从声明生成，
**插件只提供 PNG**。

### 1.2 物品（`$世界.注册物品` + 对象方法）

基底、名称、模型、贴图、堆叠、颜色、稀有度、耐久、描述（多行 + 逐行颜色）、属性修饰符、创造页归属。

### 1.3 世界 / 玩法

- **133 个 `世界` 方法**：方块读写、实体、粒子、音效、容器、掉落物、传送、时间天气、MOTD、图标、指令、GUI、悬浮字、对话框、输入框……
- **267 条 NeoForge 事件**（中英双键，6 个内置中文 + 8 个中文别名）
- **皮肤**（`/皮肤`）、**更新提示**（`ModUpdater`）、**自发布**（25568 `manifest.json` + `latest.jar`）

### 1.4 逃逸口

`$java.eval <代码|*.java>$` —— 内存编译并把结果注入词库。**任何"原语不够用"的场景都能在这里补完**，
代价是失去声明式的可移植性。

## 二、原语层（引擎实现，词库调用）

这些**不能**下放给词库，因为它们是引擎能力而不是策略：

| 原语 | 为什么必须在引擎里 |
|---|---|
| `寻路` / `可达` / `巡逻` | 原版没有"走到坐标"命令，腿是 `PathNavigation` |
| `收取掉落物` / `容器空位` | 需要 `Container` 接口 + 合并规则（`Containers.java`） |
| `刷怪蛋生成` | 复刻原版 `SpawnEggItem#useOn` 的落点算法 |
| `聚拢掉落物` | 需要逐 tick 维护堆叠（`DropStack`） |
| 事件桥 | 需要反射对接 NeoForge 事件总线 |
| 资源包派生 | 需要 zip 打包 + 25568 HTTP + sha1 |
| 注册项 | `EntityType` / `Block` 必须在启动期注册 |

## 三、仍由宿主写死（"完整接管"的剩余清单）

按"词库能做到吗 / 有什么绕法"排序：

| # | 写死的东西 | 现有绕法 | 建议 |
|---|---|---|---|
| 1 | **容器菜单**：固定 `ChestMenu`，格数→行数（9 列制） | 无（`世界.打开界面` 是另一套 GUI） | 低优先，箱子语义够用 |
| 2 | **部件数固定 2**：体 + 盖，每段一个外观方块 | 无 | 需扩方块池 → 注册项变化 → 客户端换 jar |
| 3 | **没有自然生成**：只能刷怪蛋 / `召唤` | `[事件]每秒` 自己刷（性能要自己控） | 需生成规则 DSL，成本高 |
| 4 | **驯服 / 繁殖 / 骑乘 / 装备** | 无 | 各自都是一个大系统 |
| 5 | **生物音效**（脚步、死亡、受伤） | `$世界.播放音效$` 手动播 | 可声明 `$怪.音效 键 名字$` |
| 6 | ~~右键交互~~ | — | 0.9.0 已接管：`$怪.交互 开容器\|无\|给予$` |
| 7 | ~~死亡掉落表~~ | — | 0.9.0 已接管：`$怪.掉落 物品 概率 数量$` |
| 8 | ~~实体碰撞箱注册尺寸~~ | — | 已用 `getDefaultDimensions` 绕过 |
| 9 | ~~AI 只会逛 / 看人~~ | — | 0.9.0 已接管：`$怪.目标 注视\|攻击\|逃跑\|恐慌\|漂浮$` |

## 四、刻意不接管

| 东西 | 理由 |
|---|---|
| `RandomStrollGoal` | 它会 `moveTo`，和词库下发的寻路目标抢腿 → "怪原地抽搐"的经典原因 |
| 注册表项（槽位池 / 方块池 / 创造页） | Minecraft 的注册表在启动期冻结，运行期只能改声明、不能加注册项 |
| 渲染线程 / 网络序列化 | 属于引擎内部，暴露给词库只会换来一堆时序 bug |

## 五、结论

**"完整接管"的正确含义不是「mod 里没有代码」，而是「mod 里没有玩法决策」。**

- 现在的状态：生物/物品/世界的**每一个可调参数**都在词库里；mod 里剩下的是①引擎原语、②注册期硬约束、
  ③上表第 1~8 条还没参数化的行为。
- 想再加能力时的判断顺序：
  1. 能填参数表达 → 加一个对象方法或 `世界` 方法；
  2. 需要引擎能力 → 加一个原语，判断留给词库；
  3. 都不行 → `$java.eval`，并考虑是否该把它升格成原语。
