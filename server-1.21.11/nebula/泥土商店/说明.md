# 泥土商店

用**泥土**当货币的箱子商店：`/商店` 打开界面，左键买 1 份、右键买 8 份，点商品弹确认框，成交后给物品 / 收物品。

## 1. 指令

| 指令 | 说明 |
| --- | --- |
| `/商店` / `/shop` / `/泥土商店` | 打开商店 |
| `/商店 帮助` | 打印玩法 |
| `/商店 余额` | 查背包里的泥土数量 |

指令由**词库自己注册**，写在 `main.n` 的 `[f]初始化`：

```text
[f]初始化
$世界.注册指令 商店 0 shop 泥土商店$
```

- 参数：`注册指令 规范名 [权限] 别名…`；权限是单个 `0~4` 数字，不写默认 `0`。
- 规范名决定 `%指令%` 的值（用 `/shop` 进来也是「商店」），其余是别名。
- `[f]卸载` 里写 `$世界.注销指令 商店 shop 泥土商店$`，卸载插件时移除入口。
- `/nebula load <插件>` 会执行 `[f]初始化` 并注册；`/nebula load` 幂等，不会重复注册。
- 改掉/删掉指令名后，旧入口要重启才消失（新词库的 `[f]卸载` 不会知道旧名字）。

注册后由 `[指令]` 词条处理，别名用 `|` 分隔，宿主按规范名匹配后只跑命中的那一条：

```text
[指令]商店|shop|泥土商店
参:$去除左右 %参数%$
如果:%参%==余额
    ...
如果尾
```

插件没有对应 `[指令]` 词条时返回 `ok=false`，不再回退到统一事件。

## 2. 界面

- **页签**：0 号格显示当前页；45 购买、49 回收、53 关闭。
- **余额**：4 号格显示背包里的泥土数量，点一下刷新。
- **商品**：10~33 号格；左键买/卖 1 份，右键 8 份。
- **确认弹窗**：11 确认、13 商品、15 取消。确认后先查数量再扣/给，余额或材料不足会提示并退回商店。
- 界面是只读箱子：点击不会把物品拿出来，也不会移动背包里的东西。
- 背包满时买到的物品会掉在脚下。

## 3. 配置

配置和商品目录都在插件同目录的 JSON 文件里，`[f]初始化` 读取；`/nebula load 泥土商店` 生效。开 `/nebula debug 泥土商店` 时，改 JSON 也会按文件指纹自动重载。

### 配置.json

```json
{
  "货币": "minecraft:dirt",
  "货币名": "泥土",
  "标题": "泥土商店",
  "音效开": "minecraft:block.chest.open",
  "音效点": "minecraft:ui.button.click",
  "音效买": "minecraft:entity.player.levelup",
  "音效卖": "minecraft:entity.experience_orb.pickup",
  "音效错": "minecraft:entity.villager.no"
}
```

- 换货币只改 `货币` / `货币名`，例如 `minecraft:emerald` / `绿宝石`。
- `标题` 是箱子界面标题；点击事件走闭包，不再靠标题匹配。
- 文件缺失或不是合法 JSON 时用 `配置.n` 里的内置默认值，商店照常可用。

### 商品.json

```json
{
  "购买": [
    { "槽": 10, "物品": "minecraft:diamond", "名称": "钻石", "说明": "闪亮亮的硬通货", "价": 16, "数": 1 }
  ],
  "回收": [
    { "槽": 10, "物品": "minecraft:diamond", "名称": "钻石", "说明": "回收", "价": 8, "数": 1 }
  ]
}
```

| 字段 | 含义 |
| --- | --- |
| `槽` | 界面槽位（0~53） |
| `物品` | 注册名，如 `minecraft:diamond` |
| `名称` | 展示名 |
| `说明` | 一行风味文本 |
| `价` | 单价（货币个数） |
| `数` | 每份给 / 收多少个 |

- `购买` / `回收` 各是一个数组；槽位不要重复，建议避开 0/4/8/45/49/53。
- 文件缺失或格式错误时目录为空，`[f]初始化` 会在控制台打一行警告。
- JSON 可以带缩进和空格（整文件读取，不按 `$函数 参数$` 切分）。

## 4. 界面对象与点击闭包

界面不是「全局玩家状态」，而是先创建一个**界面对象**，后续操作都带这个对象；点击逻辑写成函数值（闭包）交给它：

```text
[函数]画商店 名 页 配置 余额
面:$世界.创建界面 %名% 6 %配置.标题%$
表:$商品表$
$世界.界面物品 %面% 10 minecraft:diamond 1 "§f钻石" "§7售价 §e16 §7泥土" 是$
点击:[函数]
    点:%参数1%
    槽:%点.槽位%
    如果:%槽%==53
        $世界.关闭界面 %面%$
        返回
    如果尾
    ...
结束
$世界.打开界面 %面% %点击%$
```

- `创建界面 玩家 行数 标题…` 返回对象 id（数字字符串）；`界面物品 面 槽位 物品 数量 名称 说明 [发光]`、`界面数据 面 数据…`、`关闭界面 面` 都只作用于这个对象，且只有创建它的插件能操作。
- `打开界面 面 回调` 的第二个参数是函数值。`点击:[函数] … 结束` 在函数帧里定义，**按值捕获**当时的局部变量：`面 / 名 / 页 / 配置 / 表 / 选` 点击时都还在，不用再塞「界面数据」或全局状态表。
- 宿主点击时把 `玩家名 / 界面 / 槽位 / 按钮 / 动作 / 区域 / 物品 / 数量 / 数据 + 玩家快照` 组成 JSON，作为闭包的 `%参数1%` 传入；`点:%参数1%` 后用 `%点.槽位%` / `%点.动作%` 取值。
- 同一个玩家只保留最后 `打开界面` 的那个界面对象：重绘（切页、成交后刷新、弹确认框）会生成新对象并自动顶掉旧的，旧闭包不会再触发。玩家关窗 / 退出 / 插件卸载 / 服务端停止时对象连同闭包一起释放。
- 按玩家的旧界面方法已移除，界面一律用「对象 + 闭包」。

## 5. 实现要点

- 指令监听：`[指令]商店|shop|泥土商店`，宿主按规范名/别名匹配后只跑对应词条；没有 `[指令]` 词条时返回 `ok=false`。
- 渲染与点击都在 `界面.n`：`画商店` / `画确认` 各自创建界面对象并绑定自己的闭包；成交在 `main.n` 的 `[函数]成交`。
- 函数不继承事件作用域，配置、玩家名、选中商品都走参数传入；闭包则靠捕获，不需要再传一遍。
