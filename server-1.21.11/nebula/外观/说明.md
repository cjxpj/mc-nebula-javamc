# 外观

玩家皮肤 + 披风：**正版账号的**，或**自己上传的 PNG**。

```
/皮肤 正版 Notch          # 用正版账号 Notch 的皮肤（Mojang 签名，所有人可见；账号自带披风也会带上）
/皮肤 链接 https://…/a.png # 用网上的 PNG（服务端下载缓存，64×64 / 64×32）
/皮肤 文件 我的皮肤.png    # 用 nebula/外观/皮肤/ 下的 PNG
/皮肤 查看                # 看当前用的是哪个来源
/皮肤 清除                # 恢复登录自带的外观（皮肤 + 披风一起）
/皮肤 刷新                # 记录没变但客户端没刷出来时手动重推一次

/披风 文件 示例披风.png    # 用 nebula/外观/披风/ 下的 PNG（必须 64×32）
/披风 链接 https://…/c.png # 用网上的披风
/披风 查看                # 皮肤 + 披风各是什么
/披风 清除                # 只去掉披风，皮肤不动
```

管理（权限 2）：

```
/外观 给别人 <玩家> <操作> [参数]
  操作 = 正版 Notch | 文件 a.png | 链接 <URL> | 清除
        | 披风文件 c.png | 披风链接 <URL> | 披风清除
```

## 原理（为什么必须动 mod）

Minecraft 的外观**不是服务端渲染的**：客户端拿 `GameProfile` 里的 `textures` 属性
（base64 + Mojang 签名）自己去 `textures.minecraft.net` 下载。`textures` 里可以同时有
`SKIN` 和 `CAPE` 两个节点——所以**皮肤和披风共用同一份属性**，换其中一个必须把另一个搬过来，
否则会被顺手抹掉。换外观只有一条路：

1. 服务端改 `ServerPlayer` 的 profile 属性（`textures`）；
2. 广播 `ClientboundPlayerInfoRemovePacket` + `createPlayerInitializing`，让客户端重建
   `PlayerInfo`（皮肤缓存主键是「uuid + textures」，不重建就不会重新下载）；
3. 光重建还不够：`AbstractClientPlayer.playerInfo` 是懒加载一次就永不更新，实体还攥着旧对象。
   客户端 `NebulaSkins.rebind()` 每 tick 把它换成新实例，这才做到**不用重进就是新的**。

`SkinService` 做前两步，`NebulaSkins` 做第三步。

### 正版账号：Mojang signed

`api.mojang.com/users/profiles/minecraft/<名字>` → uuid →
`sessionserver.mojang.com/session/minecraft/profile/<uuid>?unsigned=false` → `textures` 的
value + signature。签名是 Mojang 私钥签的，任何客户端都验得过，**装不装 mod 都看得见**。
该账号如果自带披风，同一个值里就有 `CAPE`，会被一起换上。

### 自定义 PNG：本地托管 + 客户端重写

原版客户端只信任 `textures.minecraft.net`（authlib `TextureUrlChecker.ALLOWED_DOMAINS`），
所以自定义 PNG 不能写真实 URL —— 会被 `unpackTextures` 直接丢掉，连 `PlayerSkin` 都构造不出来。

做法：

1. 服务端把 URL 写成占位符 `http://nebula.invalid/nebula/skins/<文件>?v=<指纹>`，放进
   `textures` 的 `SKIN` / `CAPE` 节点（unsigned）。**原版客户端会忽略它**，
   显示默认皮肤 / 无披风，这是原版限制，不是 bug。
2. 装了星云 mod 的客户端（`NebulaSkins`）自己解析 base64 里的 URL，把 host 换成
   「当前进服用的地址 + HTTP 端口（默认 25568，见 `资源/客户端/外观.json`）」，
   交给原版 `SkinTextureDownloader` 下载（顺带做尺寸校验 / legacy 转换 / 本地缓存），
   再把拼好的 `PlayerSkin` 塞回 `PlayerInfo.skinLookup`。
3. 只认 `http://nebula.invalid/nebula/skins/` 与 `https://textures.minecraft.net/` 两种前缀，
   其他 URL 一律不碰 —— 不会变成任意 URL 加载器。
4. **披风下载时必须关掉 legacy 处理**：那个开关会把 64×32 当老皮肤升级成 64×64，
   披风用它就整块拉花；皮肤则相反，要开着。

> 结论：**自定义皮肤 / 披风只对装星云客户端的玩家可见**；正版外观所有人可见。
> 服务端的 `config/nebula-bridge/pack.properties` 改了端口，`资源/客户端/外观.json` 的
> `端口` 也要跟着改（资源包会自动重推，客户端下次进服读新声明）。

## 文件位置

| 内容 | 路径 |
| --- | --- |
| 玩家记录（跨重启） | `config/nebula-bridge/skins.json` |
| 手动放的皮肤 | `nebula/外观/皮肤/*.png`（本插件目录，建议） |
| 手动放的披风 | `nebula/外观/披风/*.png` |
| 链接下载的缓存 | `nebula/_skins/`、`nebula/_capes/`（下划线开头，引擎不扫） |
| 客户端下载缓存 | `<客户端 .minecraft>/nebula-skins/<uuid>-<hash>.png` |

改 `配置.json` 后 `/nebula load 外观`；换贴图文件**不用**重载。

## 已知限制

- 自定义外观在**其他玩家眼里**需要他们也装 mod；不装 = 默认皮肤 / 无披风。
- 正版外观每次进服会用 6 小时内的缓存值，过期后异步重新拉；拉不到就保持上一次的。
- 名字带空格 / `%` 的输入会被词库吃掉，只接受字母数字下划线。
- 皮肤尺寸只认 64×64 / 64×32；披风只认 64×32（客户端只读左上 10×16）。
- 自定义皮肤 PNG 一律按 wide 处理（文件名看不出模型）；slim 只有正版皮肤按 Mojang 元数据走。
- `/皮肤 正版` 是整份替换：会连披风一起换成那个账号的（没有披风就变成无披风）。
