# 右键坐下

空手右键**台阶 / 楼梯**坐下，潜行起身。手感对齐插件服的经典 Sit 类插件：只认"能坐的方块"，
不去抢箱子、工作台、门的右键。

## 玩法

| 操作 | 效果 |
| --- | --- |
| 空手右键**台阶 / 楼梯** | 坐在它上面（自动坐半格） |
| `/坐下`（别名 `/sit`） | 原地坐下 |
| `/起身`（别名 `/stand`） | 站起来 |
| **潜行** | 站起来（原版下车行为） |

坐下时动作栏提示「已坐下 · 潜行起身」，音效可关。坐垫完全不渲染、无碰撞、无血条，
起身后 1 秒内自动回收，世界里不会留隐形实体。

## 原理

坐垫是一个 **0×0 的 `minecraft:interaction`**：

```
summon minecraft:interaction <x> <y> <z> {width:0.0f,height:0.0f,Tags:["nebula_seat","nebula_seat_<玩家名>"]}
```

然后 `ride <玩家> mount <坐垫>`，客户端就把玩家渲染成坐姿。坐垫 Y 就是坐面高度
（真机验证：乘客 `Pos` 与坐垫 `Pos` 完全重合）。台阶 `type=bottom` / 楼梯 `half=bottom`
坐半格，`top` 与整方块坐整格（靠 `取方块数据` 的 BlockState 文本判断）。

### 为什么不用盔甲架

一开始用的是 `{Invisible:1b,Marker:1b}` 盔甲架，踩到两个硬事实：

1. **坐骑血条**：`Entity#showVehicleHealth()` 的实现就是 `return this instanceof LivingEntity`，
   骑任何活体（盔甲架也算）原版 HUD 就会画心形血条。`interaction` 不是活体 → 没有血条。
2. **marker 盔甲架不能骑**：`Marker#canAddPassenger` / `couldAcceptPassenger` 恒返回 false，
   只有**非 marker** 的盔甲架能当载具（而它还会渲染出来）。

`interaction` 是纯隐形锚点：不渲染、无碰撞、不 tick，只承担 passengers 这件事。

### 坐垫怎么回收

```
execute as @e[type=minecraft:interaction,tag=nebula_seat] at @s unless entity @a[distance=..8] run kill @s
```

判据是「坐垫周围 8 格内有没有玩家」，**不能**用 `unless data entity @s Passengers`：
实测**玩家当乘客时载具的 `Passengers` 是空的**（牛当乘客会写、玩家不写），
用它判空会把玩家正在骑的坐垫当垃圾清掉——这就是"坐下瞬间又起来"的原因。

另注意 `execute as` **只换执行者、不改坐标**，所以 `distance` 前面必须补 `at @s`，
否则距离是从命令源（世界出生点）量起的，坐垫一召唤就会被判成"附近没人"。

### 为什么不用「下车事件」即时清理

插件服那些 Sit 插件（Bukkit / Spigot）靠 `VehicleExitEvent` 在下车瞬间就把坐垫删掉，不用轮询。
这个宿主拿不到等价物：`EntityMountEvent`（带 `isDismounting()`）虽然在事件清单里，
但 **1.21.11 的服务端里没有任何代码触发它**——patched 服务端 jar 里对 `EntityMountEvent`
的引用是 0 处。实测：挂一个监听 `EntityMountEvent` 的词库，用牛骑上再下来，
探针文件一个字节都没写。所以这里只能退化成每秒一次的轮询，判据就得选"附近有没有玩家"。

（对照表：能搬的是**架构**——隐形锚点 + `ride`、只认台阶/楼梯、潜行起身、空手才坐；
搬不动的是**原语**——下车事件、`Invisible` NBT、marker 盔甲架可骑、`Passengers` 对玩家有效。）

## 配置（`配置.json`）

```json
{
  "启用": true,
  "仅空手": true,
  "任意方块": false,
  "只坐顶面": false,
  "空气可坐": false,
  "偏移": 0.0,
  "提示": true,
  "音效": "minecraft:block.wool.place"
}
```

| 键 | 说明 |
| --- | --- |
| `启用` | 总开关；关掉后右键 / `/坐下` 都不落座（`/起身` 仍可用） |
| `仅空手` | 主手拿东西时右键不坐下（拿方块、拿剑都不会误触） |
| `任意方块` | `false` = 只认台阶 / 楼梯（方块名含 `_stairs` / `_slab`）；`true` = 任何方块都能坐 |
| `只坐顶面` | 只在右键**顶面**时坐。默认 `false`：台阶侧脸右键也该坐上去 |
| `空气可坐` | 空手右键空气原地坐下。默认 `false`，避免随手右键就坐下 |
| `偏移` | 坐面再抬高多少格，微调视觉高度用 |
| `提示` | 是否发「已坐下 · 潜行起身」动作栏提示 |
| `音效` | 坐下时给玩家放的音效 id |

改完 `/nebula load 右键坐下` 生效；开了 `/nebula debug 右键坐下` 后改 json 会自动重编译。

## 已知边界

- **同一格两人坐**：各自有独立坐垫，会叠在一起（原版坐垫高度无法错开）。
- **地毯 / 雪层 / 耕地**这类不足一格的方块按整格算，会略微悬空；`任意方块=true` 时更明显，
  要精确只能下沉到 Java 侧取碰撞盒。
- **副手持方块右键**：主手空而副手有方块时，原版仍会垫方块，同时也会坐下（事件里看不到副手）。
- 不判"是否已在骑乘"：1.21.11 的实体 NBT 里已经没有 `RootVehicle`，骑在马上右键只会多一个
  1 秒内被回收的隐形坐垫，不会把人从马上拽下来。

## 词库坑位记录（踩过的）

1. `如果:$查找字 %数据% type=bottom$!=-1` 这种**条件里塞内联调用 + 负数字面量**的写法真机永远走
   else（`如果:$文本长度 %x%$>0` 这种同型写法却是好的）。凡是 `查找字` 一律先赋值再 `如果:%变量%!=-1`。
2. 空 ItemStack 在事件 payload 里是 `{item:"",count:0}`，判空手要用 `$文本长度$`，不能比 `air`。
3. `取方块数据` 返回 `Block{minecraft:oak_slab}[type=bottom,waterlogged=false]`，含 `{` `[` 的串
   只能先赋给变量再当实参，写成字面量整行会退化成文本。
4. 每个 `$调用$` 都要以 `$` 收口；`[函数]` 帧读不到 `[f]初始化` 的配置，必须显式传参。
5. 玩家当乘客不进载具的 `Passengers` NBT；`execute as` 不带坐标——任何一条都能让"看起来对"的
   清理逻辑把玩家连人带垫一起清掉。
