# 登录插件

账号密码登录，密码用 **MC 1.21.6+ 的原版 dialog 弹窗** 输入：进服后弹出密码输入框，输完点右侧「提交」即以 `/npw <整串密码>` 完成验证；左侧「退出服务器」按钮可随时主动断开。

密码一律 3-20 位数字；首次进服输两次设置，之后每次输一次；切换配置后 `/nebula load 登录` 立即生效。

## 玩家看到的流程

1. 进服 → 被**传送到出生点**并切到**旁观模式**：不能攻击、破坏、放置、用物品、开箱子，怪物也不会索敌；
   同时挂上**失明 + 缓慢 + 隐身 + 无敌**（模式切换万一失败也有兜底），屏幕中央显示「星云登录」。
2. 弹出**密码输入框**（原版 dialog）：框里输入 3-20 位数字，点右侧「提交」即发送整串密码完成一步验证；
   弹窗正文写清**密码规则 / 错误次数 / 上一次失败原因**；**剩余秒数走动作栏**每秒刷新，不刷聊天。
3. **首次进服**：输一遍 → 提示「第一步完成」→ 再输一遍相同的 → 两次一致就创建账号，立刻**传送回进服位置、恢复原游戏模式、清掉失明/缓慢**。
4. **已注册**：输一遍正确密码即放行；输错会**重新弹出输入框**，正文标出「密码错误 · 错误 N/5 次」，连续错 5 次踢出。
5. 300 秒没完成验证会被踢出。

未验证期间跑不掉：每秒检查一次坐标，离开出生点就被拉回来；旁观模式下攻击 / 破坏 / 放置 / 交互全被客户端禁掉；聊天会被吞掉并提示用弹窗输入。

> **点太快会被原版踢**：Minecraft 对聊天/指令有「20 条 / 20 秒」的限流，点击按钮也算一条。
> 正常节奏输入（3-20 位 + 确认）不会触发；如果连续重试很多次，可能先被 `disconnect.spam` 踢下线。
> 所以 `最长` 默认是 20 位：一次提交只算一条指令，长度本身不吃限流额度。

## 指令

| 指令 | 权限 | 说明 |
| --- | --- | --- |
| `/登录`（`/login` `/l` `/登陆`） | 0 | 重新弹出登录弹窗（弹窗被关掉、或想重来时用） |
| `/nquit` | 0 | **弹窗内部指令**：左侧「退出服务器」按钮点击时由客户端发出，主动断开连接；不用手敲 |
| `/npw <密码>` | 0 | **弹窗内部指令**：提交按钮把整串密码发回来，不走聊天 |
| `/重设 <在线玩家>` | 2 | 清掉对方账号，强制重新设置密码；对方会被踢下线 |

> 注意：`世界` 的指令名按正则匹配（`A|B|C` 会被当成正则的或），重置用 `重设`——不要起成「登录xx」或含 `l` 的名字，否则会被 `[指令]登录|login|l|登陆` 抢走。

## 目录结构

```text
nebula/登录/
├── main.n / 界面.n / 账号.n   ← 词库代码
├── 说明.md / nebula.ini
└── data/                      ← 运行数据（插件自己建，可整目录备份）
    ├── 账号.json
    ├── 会话.json
    ├── 原状态.json
    └── 配置.json
```

## 数据文件

运行数据都在 `data/` 下，代码目录只有 `.n` 和说明。

| 文件 | 内容 |
| --- | --- |
| `data/账号.json` | `{UUID: {名, 密码, 注册, 上次, 次数, 失败}}`，密码是 `sha256(盐 + UUID + 密码)` 的十六进制 |
| `data/会话.json` | 未验证玩家的临时状态：`态 / 输入 / 暂 / 错 / 截止 / 模式 / 失败 / 已提示 / 原x,y,z,原维度 / 出x,y,z`；`错` 是上一次失败原因，弹窗发出后即清掉；玩家离线整条会被清掉 |
| `data/原状态.json` | `{UUID: {模式, 维度, x, y, z}}` —— **冻结前**的真实状态，按 UUID 持久化；验证成功后删除。整个目录备份时要一起带走 |
| `data/配置.json` | 见下；`盐` 第一次运行自动生成，**改了它所有旧密码都会失效** |

> **为什么需要 `原状态.json`**：会话会被清理，但玩家存档会把「旁观模式 + 冻结坐标」写进磁盘。
> 只靠会话记原状态，未验证就退出再进服时抓到的就是旁观 + 出生点，解冻后又恢复成旁观，
> 形成「退出重进永远是观察者」的死循环。这张表按 UUID 跨重连 / 重载 / 重启存活，
> 只在确认玩家还没被冻结时写一次，之后一律复用，绝不重新抓当前状态。

```json
{
  "盐": "",
  "超时": 300,
  "最短": 3,
  "最长": 20,
  "失败上限": 5,
  "成功音": "minecraft:entity.player.levelup",
  "错误音": "minecraft:entity.villager.no",
  "提示音": "minecraft:block.note_block.pling"
}
```

## 边界情况

- **断线重连**：会话按连接重建（`[事件]玩家进入`），上一次「已登录」不会带到新连接，重连必须重新验证；
  但**原模式 / 原坐标从 `原状态.json` 复用**，不会因为存档里已经是旁观就把旁观当成「原来的模式」。
- **未验证就退出**：原状态不会随会话一起被清掉。重连后存档里仍是旁观（这是原版写盘行为，词库改不了），
  但登录成功一定恢复到冻结前的真实模式与坐标，不会卡在观察者。
- **关服 / 重载**：`[f]初始化` 把所有「已登录」降级成「登录」，防止重启后直接进服绕过密码。
- **登录后回原位**：坐标（取整）、维度和模式取自 `原状态.json`，验证通过后 `传送玩家` 回去并恢复原模式；
  旁观 / 冒险 / 空值一律按不可信的冻结态回退生存，维度缺失回退主世界。
- **提交会关闭弹窗**：原版 dialog 的 `after_action=close` 让每次提交后弹窗都消失。所有校验失败分支
  （太短 / 非数字 / 过长 / 两次不一致 / 密码错误）统一走 `记错 → 发面板` 重新下发，顺带刷新正文里的
  错误次数；否则就是「输错一次密码，输入框就没了」。
- **按钮模板必须带哨兵前缀**：原版宏模板要求至少一个 `$(变量)`，纯文本 `nquit` 会让模板解析失败，
  宿主因此补成 `nquit #$(pw)`（`#` 是哨兵）。**这个 `#` 不是装饰**：输入框为空时 `$(pw)` 会实例化成
  空串，命令就成了 `nquit `——literal 后面只剩一个空格、没有参数内容，Brigadier 判
  `Incorrect argument for command`（客户端显示「错误的命令参数」+ `nquit <--[此处]`，看起来像指令不存在）。
  加了哨兵后空输入也得到 `nquit #` 这种合法 token。`[指令]nquit` 不读参数直接忽略；
  `[指令]npw` 用 `$替换 %参% "#" ""$` 先剥掉前缀（密码是纯数字，不会含 `#`）。
- **剩余秒数只能走动作栏**：弹窗正文是「打开那一刻的快照」，写死的秒数不会自己走；想让它动就得重下发，
  而重下发会清掉玩家已经输入的数字——所以倒计时放 `[事件]每秒` 的 `世界.动作栏`（每秒一条，验证通过后
  客户端 3 秒自动淡出）。最后 15 秒转红提示「即将断开」。拼正文不能带空格，否则会被按空格切成多个参数。
- **两次输入不一致**：退回第一步重新设置，不写库。
- **长度不对**：小于 `最短` / 大于 `最长` 在弹窗正文里标出原因，不计失败次数。
- **跑出出生点**：每秒拉回一次；跳跃 / 走动都离不开。
- **旁观模式**：原版里唯一能保证「什么都做不了」的状态——攻击 / 破坏 / 放置 / 交互 / 用物品全部由客户端直接禁掉，
  不依赖我们拦事件；聊天在旁观下照常可用，所以未验证期间发聊天会被提示用弹窗输入。
  代价就是未验证退出会把旁观写进玩家存档，所以才有 `原状态.json` 做兜底。
- **出生点查询**：宿主 `世界.取复活点坐标` 在 1.21.11 曾因旧 getter 被删而恒返回 `{}`，
  空坐标会被当成 `0 0 0` 把玩家塞进方块里。现在宿主改用 `getRespawnData/pos` 取真实出生点；
  词库侧也加了保护——查不到就不传送，只原地冻结，归位检查自动跳过。
- **无敌 + 隐身**：`设置无敌` 走 `abilities.invulnerable`（实测 `/damage` 返回 invulnerable），同时挂 `minecraft:invisibility` 效果 + `设置隐身` 标记，僵尸等怪物的 Brain 里不会出现 attack_target（实测召唤僵尸后 `Brain: {memories: {}}`）。
- **缓慢等级**：用 128 级（amplifier 127）；写 255 会溢出成 -2（负等级 = 加速），别改大。

## 依赖

- 宿主需要 `[事件]玩家进入`、`[事件]每秒` 和 `世界.弹窗输入`（本仓库 `NebulaMod` / `DialogUi` 已实现，需 MC 1.21.6+）。
  `弹窗输入` 传第 7 个可选尾参 `nquit` 时，宿主改用 `MultiActionDialog`，在「提交」左侧加一个「退出服务器」按钮；
  省略该尾参就退回单按钮 `NoticeDialog`，其它插件不受影响。
- `世界.取复活点坐标` 取世界出生点；`世界.传送玩家` 做冻结与回位。
