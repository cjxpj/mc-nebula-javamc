# 箱子生物

`nebula:chest_creature` —— 词库声明的通用生物（`DynamicMob` 的槽位实例，**不是**隐形猪换皮）。
**贴哪张图、偏移多少、怎么弹跳开盖，全在这个插件里**：`$怪.外观$` 定画哪个方块，`$怪.动画$` 定弹跳与开盖，
宿主按槽位把模型 / 贴图 / 客户端声明派生进资源包。mod 侧**没有任何品种特判**：
造型是「体 + 盖」两个**可声明的盒子**（缺省就是箱子形），换贴图、改盒子、调 UV 都不用碰 Java。

## 用法

```
创造模式 →「生成蛋」页 → 箱子生物蛋        # 条目由 $怪.加物品 声明，随资源包下发
右键方块                                    # 在你点到的那个方块上放出，扣 1 颗蛋
右键箱子生物                                # 开 27 格箱子
```

- **没有 `/物品` 指令**（宿主的指令只有 `/nebula`）。要发放就进创造页，或自己 `give` 原版基底物品。
- **蛋是真刷怪蛋，本插件不挂任何右键事件**：`$怪.加物品 刷怪蛋 …$` 声明「用途=刷怪蛋」后，宿主把基底换成
  `nebula_bridge:spawn_egg` + `entity_data` 组件，于是它就是原版 `SpawnEggItem`。
  右键方块走原版 `useOn`：落点、扣蛋、音效、发射器、改名传递全白拿，词库一行事件都不用写。
- **落点规则**（原版算法）：视线射线取点击方块 → 无碰撞就生成在这一格 → 有碰撞挪到点击面外侧、顶面再抬一格。
  **不是** `summon ~ ~ ~` 的玩家脚下。
- 想自己控制落点 / 加生成特效，才需要挂 `[事件]右键方块`（`PlayerInteractEvent.RightClickBlock`，
  1.21.11 里「看着方块右键」只发这个事件）+ `$世界.刷怪蛋生成 玩家 类型 标记$` + 成功后 `$世界.取消事件$`。
  **别挂 `[事件]右键物品`**：它只覆盖「客户端没命中方块」的 `useItem` 路径，挂错的表现是点方块不触发、点空气才触发。

## 它长什么样

造型是**两个外观方块**，不是一个模型（下表是缺省盒子，可用 `$怪.造型$` 改）：

| 方块 | 范围（方块坐标 0..1） | 贴图用法 |
|---|---|---|
| `nebula_bridge:mob_body_<槽位>` | 体，`y 0..14/16` | 四面整图（那张脸），顶 / 底取贴图底部 4 行深色 → 开盖后看到「箱内」 |
| `nebula_bridge:mob_lid_<槽位>` | 盖，`y 14/16..16/16` | 四面与顶取贴图**最上面 3 行**浅木色带；底面深色 |

**为什么拆两个**：方块模型是一次性提交的整体几何（`submitBlock` 一次一个 `BlockState`），
模型里有几个 element 都算一整块，没法只旋转「盖」那部分。拆成两个方块状态，渲染器才能给盖子单独摆 pose。

贴图只有一张：`资源/方块材质/chest_creature.png`（16×16，木箱 + 红眼睛）。
**换皮肤 = 换这张 PNG + 重启服务端**，不用重编 jar。

## 自定义造型（`$怪.造型$` / `$怪.贴图$`）

缺省造型是「`0..14` 的箱体 + `14..16` 的盖」。想换形状就声明盒子，坐标是方块坐标的
**1/16 单位**（`0..16`，可带小数）：

```
$怪.造型 体 1 0 1 15 14 15$     # 体 fromx fromy fromz tox toy toz
$怪.造型 盖 1 14 1 15 16 15$     # 盖 同上
```

- **两个盒子各自独立**：只写 `体` 就只改箱体，盖子留在原处（重叠或悬空自己负责）。
- **造型本身只影响渲染**：碰撞箱、交互距离、寻路体积默认仍按 `体型` 档。要让碰撞箱跟着造型走，
  写 `$怪.设 碰撞箱 自动$`（见下一节）—— 否则会出现「看着变小了、实际还是那么大」。
- **开盖铰链跟着盖子走**：铰链 = 盖子顶面 + 方块后边界（`y = 盖.to.y / 16`、`z = 1.0`），
  所以改盖子高度后它仍绕自己的后上边缘转；z 固定在方块后缘，把盖子整块挪到前半格会显得绕远转。
- 贴图文件仍是 `$怪.外观$` 第 3 参那张，造型只是决定「这张图贴到哪个盒子上」。

某几面的 UV 不满意可以逐面覆盖（面 = `北` `南` `东` `西` `上` `下` `全部`）：

```
$怪.贴图 体 上 0 12 16 16$
$怪.贴图 盖 上 0 0 16 3$
```

不写就是这套缺省：

| 部件 | 四面 | 上 | 下 |
|---|---|---|---|
| 体 | 整图 `0,0,16,16` | 贴图底部 4 行 `0,12,16,16` | 同左 |
| 盖 | 顶部 3 行 `0,0,16,3` | 同左 | 贴图底部 4 行 `0,12,16,16` |

UV 允许 `-32..32`（平铺），但**别超出贴图**：客户端不报错，只会画出拉伸或重复。

### 多张贴图（`$怪.材质$`）

缺省只有一张主贴图（`$怪.外观$` 第 3 参，模型槽位叫 `crate`）。想给某些面单独一张图：

```
$怪.材质 眼睛 nebula_bridge:block/chest_eye$     # 注册一个材质别名
$怪.贴图 体 北 0 0 16 16 眼睛$                  # 第 7 参指定这一面用它
```

- 材质名是词库里的别名，宿主按**字母序**编成 `t0` / `t1`…（模型槽位名必须 ASCII，中文名不行）。
- 第 7 参省略 = 用主贴图。
- 图片照样放 `资源/方块材质/`（→ `textures/block/`）；名字写错不会渲染崩，会退回主贴图并在日志 WARN。

### 碰撞箱（`$怪.设 碰撞箱 …$`）

```
$怪.设 碰撞箱 自动$          # 按 $怪.造型$ 的两个盒子算：宽取 x/z 跨度、高取最高点
$怪.设 碰撞箱 0.6,0.9$       # 或者直接写「宽,高」（格）
```

- 不写就用体型档的注册尺寸：`tiny 0.5×0.5` · `small 0.9×0.9` · `normal 0.6×1.8` · `large 1.5×2.0`。
- `自动` 只吃 `$怪.造型$` 的盒子；没写造型时等同于不覆盖。
- 本插件写的是「自动」→ 宽 `0.875`、高 `1.0`（体 1..15 + 盖 14..16 的并集）。
- 碰撞箱影响**寻路、穿门、挤压**：造型视觉改小但碰撞箱没跟着改，就会出现「看着能过、实际过不去」。
- 改完 `/nebula load 箱子生物` 立即生效，已生成的怪也会重新算包围盒。

## 右键交互（`$怪.交互$`）

```
$怪.交互 开容器$                    # 缺省：有容器就开菜单
$怪.交互 无$                        # 什么都不做，把右键交还给 [事件]右键实体
$怪.交互 给予 minecraft:apple 3$    # 右键给 3 个苹果
```

- `给予` 是唯一带参数的类型，物品 id 要写全名（`minecraft:apple`）；写错等于右键没反应。
- `无` 返回 PASS，所以 `[事件]右键实体` 照样能收到 —— 想做对话 / 商店 / 收租就走这条路。
- 连着右键有 **10 tick 冷却**：原版右键能连点，没冷却就是刷物品机。
- 玩家背包满时物品掉在脚下（和原版 pickup 一致）。

## 死亡掉落（`$怪.掉落$`）

```
$怪.掉落 minecraft:gold_nugget 0.5 2$   # 物品 概率 数量
$怪.掉落 minecraft:stick$              # 不写概率 = 必掉，数量 = 1
```

- 和 `死亡掉落` 字段**互不影响**：那个只管「容器里装的东西撒不撒」。
- 概率 `0..1`（写 >1 按 1 算），数量 `1..64`；物品 id 写错就不掉，不崩。

## AI 目标（`$怪.目标$`）

缺省只有「浮在水上 + 随机张望 + 8 格内看玩家」。想让它做别的事：

```
$怪.目标 注视 玩家 12$         # 类型 对象 距离（度/格按类型）
$怪.目标 攻击 玩家 1.1 16$     # 对象 速度 索敌距离 → 装 NearestAttackableTarget + MeleeAttack
$怪.目标 逃跑 玩家 8 1.4$      # 对象 触发距离 逃跑速度 → 装 AvoidEntityGoal
$怪.目标 恐慌 1.2$             # 受伤后逃跑速度 → 装 PanicGoal
$怪.目标 漂浮$                 # 常驻的 FloatGoal（已内置，写不写都一样）
```

- 「对象」认 `玩家` / `怪物` / `动物`（写错就跳过这条，不报错）。
- **只做原版 Goal 的参数装配**，不写新 AI —— 路径、视线、攻击冷却全跟原版一致。
- 没声明任何「注视」时，宿主补一条 8 格看玩家的缺省注视，保持「怪会看着你」的观感。
- ⚠️ 攻击 / 逃跑 / 恐慌 会自己 `moveTo`，**和 `$世界.巡逻$` 抢同一条腿**。声明了它们就别再用巡逻：
  两边互相顶掉目标，表现为原地抽搐。散步归巡逻管，打架归目标管，二选一。

## 动画（`$怪.动画$`）

```
$怪.动画 弹跳 0.14$      # 走路每步抬起多高（格）
$怪.动画 前倾 80$        # 跳起时向前点头的最大角度
$怪.动画 开盖 100$       # 盖子全开转过的角度
$怪.动画 开合 0.18$      # 每 tick 的开合进度步进，越小越慢（0.18 ≈ 5.5 tick）
$怪.动画 摇摆 6$         # 走路左右摇的最大角度（度），站着不动自动归零
$怪.动画 缩放 1.08$      # 呼吸缩放倍率，1 = 不动，一个来回约 2 秒
$怪.动画 旋转 30$        # 每秒自转多少度（浮游 / 旋风类造型）
$怪.动画 浮空 0.15$      # 整体抬高多少格（漂浮生物，不随走路变化）
```

前七个是**客户端渲染量**，宿主写进 `assets/nebula/client/mob_<槽位>.json`；
`开合` 是唯一留在服务端的量（开合进度由服务端算、同步给客户端）。
- **开盖只在容器生物上有动作**：玩家右键打开容器时盖子转开，关界面 / 走出 `容器距离` 格 / 掉线自动合上
  （走原版 `ChestMenu` 的 `startOpen` / `stopOpen`，成对，计数不会漏）。
- **弹跳对所有生物生效**，幅度乘行走速度——刚起步和快停下自然收小，站着不动高度归零。
- 八项都可省，省了吃缺省值（除了 `弹跳`/`前倾`/`开盖`，其余缺省都是「不起作用」）。
  **调这八个数不用换客户端 jar**。

## 声明清单（哪些真的生效）

词库里每一个 `$怪.…$` 到底改了什么，照这张表查（0.6.6 审计过一遍）：

| 声明 | 实际效果 | 备注 |
|---|---|---|
| `名称` `体型` / `血量` `速度` `跳跃` `击退` | 语言名 / 槽位档 / 三项属性 + 击退抗性 | 体型决定分到哪一档 8 个槽位 |
| `容器格数` | 容器容量 | `0` = 不是容器，右键不开箱也不能巡逻捡物；上限 54 |
| `容器距离` | 玩家离多远还能开着箱子 | **0.6.6 起生效**，钳到 1..64 格 |
| `死亡掉落` | 死后把容器内容撒出来 | 缺省「是」 |
| `持久` | 不被自然清除 | 缺省「是」，本插件没写 |
| `外观` 的 `贴图` / `偏移` / `阴影` | 派生 blockstate、方块模型、客户端声明 | 换皮肤 = 换 `资源/方块材质/*.png` |
| `外观` 的第 2 参 `方块模型` | ❌ 按槽位覆盖 | 写错只 WARN，见踩坑 10 |
| `造型` | 覆盖 体 / 盖 两个盒子的几何（1/16 格坐标） | 只影响渲染，见「自定义造型」 |
| `贴图` | 逐面覆盖 UV，第 7 参可指定材质 | 面 = 北/南/东/西/上/下/全部 |
| `材质` | 注册额外贴图，供 `贴图` 按面引用 | 名字编成 `t0`/`t1`，须 ASCII |
| `碰撞箱` | `自动`（按造型算）或 `宽,高` | 不写 = 体型档尺寸；影响寻路/穿门 |
| `目标` | AI 目标（注视/攻击/逃跑/恐慌/漂浮） | 原版 Goal 参数装配；与 `巡逻` 抢腿 |
| `交互` | 右键行为：开容器 / 无 / 给予 | `给予` 带 10 tick 冷却 |
| `掉落` | 死亡时的额外掉落（物品 + 概率 + 数量） | 与 `死亡掉落` 互不影响 |
| `动画` 的 `弹跳` / `前倾` / `开盖` | 客户端渲染量 | 走资源包，不用换客户端 jar |
| `动画` 的 `摇摆` / `缩放` / `旋转` / `浮空` | 客户端整体变换 | 缺省都不起作用（0.8.0） |
| `动画` 的 `开合` | 服务端开盖速度 | 唯一留在服务端的动画量 |
| `加物品` | 蛋（真 `SpawnEggItem`）+ 创造页条目 + 物品模型 | 第 6 参 `贴图` 优先于 `模型` 推导 |
| `分类` / `行为` | ❌ 宿主不读（空字段） | 别在这上面花时间 |

## 分层（本项目的标准姿势）

| 层 | 位置 | 职责 |
|---|---|---|
| 实体机制 | `NebulaLoadMod/.../content/DynamicMob.java` | 通用生物：容器（格数与交互距离都来自声明）、右键菜单、死亡掉落、存读档、开合进度同步。**不注册任何 MOVE 目标** |
| 品种表 | `.../content/MobRegistry.java` | 品种 → 槽位分配；派生 blockstate / 模型 / 客户端声明 / 语言 / 创造页 |
| 外观方块 | `.../content/NebulaBlocks.java` | `mob_body_<i>` / `mob_lid_<i>` 两套池子，无碰撞、不放置、不掉落 |
| 渲染 | `src/client/java/.../DynamicMobRenderer.java` | 体 + 盖各提交一次；弹跳与开盖都在这里，参数从声明读 |
| 默认策略 | `McApi.java` 的 `巡逻` | 一行 `$世界.巡逻 实体 [半径] [追速] [闲速] [溜达]$` |
| 声明 | `nebula/箱子生物/main.n` | `[f]初始化` 里 `$怪.设 / 外观 / 动画 / 加物品 / 生效$`；`[事件]每秒` 遍历巡逻 |

**为什么「走路」不能纯词库**：原版没有「走到坐标」这种命令，腿是引擎的 `PathNavigation`。
mod 只出一个 `寻路` 原语（下目标、返回有没有路），其余判断全在词库。
`实体传送` 那种做法是逐 tick 改坐标，会抖、会穿墙，不考虑。

## 构建 / 部署

```
powershell -File NebulaLoadMod/build.ps1            # 只改 Java / 词库 / 资源
powershell -File bridge/pack.ps1                    # 改了 bridge/src（引擎）必须走这个
```

- 版本号唯一源 `META-INF/neoforge.mods.toml`（当前 0.9.0）。**两端必须同 jar**：
  服务端注册 `mob_lid_*` 之后，客户端拿旧 jar 会在配置阶段被 registry sync 拒掉（不是掉线提示，是连接被拒）。
- **换客户端 jar 必须先关游戏**：运行中的 JVM 锁着文件，删不掉也改不了名。
- 注册项（`NebulaEntities` / `NebulaBlocks` / `NebulaCreativeTab`）没变的改动，`build.ps1` 会打印
  `Registry: unchanged`，客户端可以不换；但这行提示被并发构建污染过，真假要看 jar 里有没有新字段。

## 踩过的坑

1. **资源包路径必须是 ASCII**：原版 `FilePackResources` 白名单只认 `[a-z0-9_.-]`，
   含中文的文件名整条丢弃，只在客户端日志留一行 `Invalid path in datapack: … ignoring`——
   那份声明等于不存在（外观看不见、更新提示失效，服务端一点错都不报）。
2. **`$调用$` 漏结尾 `$`**：症状是「插件加载成功、功能全哑」，引擎给 `main.n:行号` 的 `NEB0004`。
   改完先数一遍 `$`（注释里的不算）。
3. **函数里 `%参数.字段%` 拿不到值**：`$巡逻 %怪.uuid%$` 传进去的是字符串，函数体内 `%怪.x%` 是空的。
   要在外面先 `mx:%怪.x%` 再整组传参。
4. **mod 里不能留 `RandomStrollGoal`**：它 `start()` 会直接 `moveTo`，把词库下发的目标顶掉。
5. **物品 Y 不一定是整数**（半砖 / 树叶 / 地毯）：`walkY()` 归一（整数格取 `floor`，小数格抬一层）。
   用 `/summon` 摆悬空靶子会自己掉到地面，想测「够不着」要用封闭石房。
6. **空服暂停会骗人**：`pause-when-empty-seconds`（默认 60）一到，整个 tick 循环停住、实体全冻，
   `[事件]每秒` 也停——测试时先确认有玩家在线，否则会得出「站着不动」的假结论。
7. **方块模型的贴图必须放 `方块材质/`**（→ `textures/block/`）：方块模型只会把 `block/` 目录的贴图
   加进方块图集，引用 `textures/entity/` 会报 `Missing textures in model …` 并渲染成品红/黑缺图格。
8. **服跑着别构建**：覆盖正在被 JVM 读的 jar 会 `NoClassDefFoundError` 崩服；改完先 `stop`。
9. **`[事件]右键物品` 不是「右键任何东西」**：它只覆盖没命中方块的 `useItem` 路径。
   凡是要「点到的方块坐标 / 面」的功能（自己控制落点的生成、放置类），一律挂 `[事件]右键方块`。
   本插件曾经照 `docs/apis/事件.md` 里那句错话挂错过事件，导致蛋完全不能用（2026-11-15 修）。
   **现在蛋是真 `SpawnEggItem`，根本不用挂事件**——这条留着是为了提醒「自己写落点」时别挂错。
10. **`$怪.外观` 的第 2 参（方块模型）由宿主按槽位覆盖**：写错只在日志 WARN，不影响渲染。
    本插件体型 `small` = 第 2 档、每档 8 个槽位 → 实际槽位 **8**，所以写 `nebula_bridge:mob_body_8`。
    改体型或加同档品种后槽位会变，看日志那行 WARN 就知道实际值。
11. **`$怪.设 容器距离 n$` 从 0.6.6 起真正生效**：之前宿主 `stillValid` 写死 8 格，词库改了不起作用。
    现在夹在 1..64 格，改完 `/nebula load 箱子生物` 立即生效（已开着的界面要重开一次）。
12. **`LivingEntity#getDimensions(Pose)` 是 `final`，覆写不了**（0.8.0 踩到）：想在运行期改碰撞箱，
    只能覆写 `getDefaultDimensions(Pose)` —— `getDimensions` 只是
    `getDefaultDimensions(pose).scale(getScale())`。改完还得调 `refreshDimensions()` 重算包围盒与
    眼睛高度，否则要等下一次 pose 变化才生效。
