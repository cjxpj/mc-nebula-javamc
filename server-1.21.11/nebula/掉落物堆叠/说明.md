# 掉落物堆叠

生电服用的掉落物聚合插件。它把**半径内的同类掉落物**聚到**总量最大的那一颗**上，由宿主
`DropStack` 合成**不限数量**的逻辑堆，从而把地面上的掉落物实体数量压下来。

## 它怎么工作

词库只出**白名单 / 半径 / 频率**，聚拢动作交给宿主原语（每维度每轮一次）：

```text
$世界.聚拢掉落物 <维度> <白名单JSON> <半径> <保护带组件> <无限堆叠>$
```

宿主按「总量降序」贪心分组：

1. 先处理的一定是这一片里**最大**的那颗 —— 它成为**主堆**，位置不动；
2. 后面比它小的同类朝它走（每轮最多 1.5 格，看得见"走过来"而不是瞬移）；
3. 水平距离进到 0.75 格（且竖直相差 ≤1.5 格）就并进主堆总量，小的实体消失。

这条规则是 2026-11-15 改的：旧版由词库逐颗 `tp` 到**最近邻**，两个方向同时命中 ——
已经堆好的大堆会反过来去追刚掉下来的小堆，看起来就是"已堆好的掉落物在附近掉落物之间来回弹"。
现在**最大的永远不动，只有小的会动**。

- 只做**聚拢**：不召唤新物品、不 `kill` 物品（并入是宿主把总量累加后丢掉小的那颗）。
- `无限堆叠: 是` 时满堆也参与；关闭时满堆留给原版合并，只聚拢零散的。
- 带任意数据组件的物品在 `保护带组件物品: 是` 时不参与；`nebula_nostack` 标签的掉落物永不参与。
- 上下层不互相吸：竖直相差超过 1.5 格直接跳过，避免把二楼的东西拽到一楼。
- 分组键是「同物品 + 同主人」；挑主堆时再比一次组件（`isSameItemSameComponents`），
  所以两把附魔不同的剑永远不会被当成同类。

## 无限堆叠怎么实现

1.21.11 的 `ItemStack.CODEC` 用 `ExtraCodecs.intRange(1, 99)` 限制 `count`，**物品栈本身
不可能超过 99**，超过会在读档时解析失败。所以总量不写进物品栈，而是由宿主保存：

- 实体仍然是普通的 `minecraft:item`，可见栈固定为一个满堆（64，物品本身上限更低时取上限），
  这样原版 `ItemEntity.isMergable` 会直接跳过它，不会绕过宿主自己合并。
- 真实总量存在实体持久数据 `nebula_total`（`NeoForgeData` 会随区块存盘），
  同时打上 `nebula_pile` 标签，指令层可以 `tag=nebula_pile` 识别。
- 宿主每 10 tick 再补一轮 0.5 格内的合并（同物品 + 同数据组件 + 同主人，同样按总量大的当主堆），
  负责"堆叠被扔在同一格"这种贴身情况；跨格的聚拢由上面的原语负责。
- 实体名牌显示的是**逻辑总量**，不是可见栈的 64。

### 拾取 / 漏斗 / 销毁

- **玩家拾取**：宿主在 `ItemEntityPickupEvent.Pre` 接管，按背包容量分批 64 个地发放，
  背包满了就留在原地，不会吞掉余量。
- **漏斗**：每次仍然搬走一个满堆（64），宿主把这次减少同步进总量；如果漏斗把可见栈整堆
  搬空、实体被原版直接 `discard`，宿主会在原地补回剩余总量，**不会丢物品**。
- **岩浆 / 火焰 / 爆炸 / 自然消失**：和原版掉落物一样整堆销毁，逻辑总量一起没了。
- **区块卸载 / 重启**：总量和可见栈都在实体持久数据里，读档后继续按逻辑堆工作。

## 数量名牌

`显示数量: 是` 时，掉落物会显示 `钻石 ×3` 这样的名牌：**物品名保留自己的稀有度颜色**
（白 / 蓝 / 金），数量部分是黄色。做法是直接写**物品实体自己的** `CustomName` + `CustomNameVisible`，
不生成任何额外实体（宿主 `DropLabel`，每 10 tick 扫一次）：

- **每一堆都挂自己的数量**：只要数量 > 1、无数据组件、没有 `nebula_nostack` 标签，就标 `×N`。
  聚拢过程中的小堆也会带着数字走过来，并进大堆后才消失。（旧版只给「同一片地里最大的那堆」挂，
  玩家看到「三堆东西只有一堆有数字」，会以为另外两堆的数量丢了。）
- 1.21.9 起重构后的 `ItemEntityRenderer.submit` 会回调 `EntityRenderer.submit` → `submitNameTag`，
  判定只看 `Entity#isCustomNameVisible()`，所以原版掉落物能直接显示自定义名牌。
- 物品名走 `translate` 键（`item.minecraft.diamond`），**跟随客户端语言**：中文客户端显示「钻石 ×3」，
  英文客户端显示「Diamond ×3」。
- 名牌就是实体字段本身：物品被拾取、吸入漏斗、掉进虚空、被合并时，名字跟着实体一起消失，
  **结构上不会留下孤儿显示实体**，重启也不会。
- 只在数量或状态变化时重写组件，平时零开销；数量掉回 1 时自动清掉名字。
- 带数据组件的物品（自定义名 / 附魔 / 容器内容等）和 `nebula_nostack` 标签的实体不挂名牌；
  别人手动给实体起的名字不会被覆盖（本插件只清理自己写过的，靠 `nebula_label` 持久标记识别）。
- 关闭 `显示数量` 后，宿主会清掉所有本插件写过的名牌；`/nebula unload` 也会把开关置为关。

## 配置

同目录 `配置.json`：

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `启用` | `是` | 改成其它值即停用扫描（插件仍加载，`/堆叠` 可查状态） |
| `间隔秒` | `2` | 每多少秒扫一轮，限制 1~60 |
| `半径` | `2` | 聚拢半径（格），限制 1~8；生电精密区建议 1 |
| `保护带组件物品` | `是` | `是` 时跳过带任意数据组件的物品（附魔、命名、容器、药水等） |
| `显示数量` | `是` | 给数量 >1 的掉落物挂 `物品名 ×N` 名牌（一片地只有主堆挂）；名牌是实体字段，不动物品栈 |
| `无限堆叠` | `是` | `是` 时由宿主合成不限总量的逻辑堆；`否` 时退回原版合并（每组 ≤64） |
| `维度` | 主世界 / 下界 / 末地 | 只在列出的维度扫描 |
| `物品` | 常见生电产出 | 只处理列出的物品注册名；不在表里的物品完全不碰 |

改完执行：

```text
/nebula load 掉落物堆叠
```

`/nebula debug 掉落物堆叠` 打开后，保存 `配置.json` 也会自动重编译。

## 指令

```text
/堆叠            查看状态（别名 /dropstack）
```

状态行包含启用状态、半径、间隔、无限堆叠开关、白名单条目数；管理员会多一行保护规则提示。

## 生电服调优建议

- **只把真正会大量产出的物品放进白名单**。宿主每轮要按维度扫一遍已加载实体，白名单越长、
  地面掉落物越多，单轮开销越大。默认表已覆盖圆石/深板岩/矿物/木头/农作物/常见怪物掉落。
- **水流分类线 / 漏斗阵列附近把半径降到 1**，避免把相邻格子的物品拉离原本的收集路径。
  聚拢只朝同一片里最大的那颗走，但半径 8 仍然会把两格外的零散产出拽过来。
- 需要保持"一组最多 64"的产线（例如按 64 计数的分类器），把 `无限堆叠` 设为 `否`，
  或把对应物品从白名单移除。
- 村民交易、任务物品、展示框里的物品不受影响；若有个别掉落物不想被移动，给它加标签：
  `tag @e[type=minecraft:item,limit=1,sort=nearest] add nebula_nostack`。
- 生电常用的"掉落物必须留在原地"场景（例如计时器踩着物品、发射器计数）建议把对应物品从
  白名单移除，或把半径设为 1、间隔设为 5。

## 验证

在空地上连续丢 1 个、2 个和 60 个圆石（相距 1 格），等一轮扫描后：

- **60 那堆留在它自己原来的位置**，另外两堆走过来并进去，最后只剩一个实体，名牌显示总数
  （`圆石 ×63`）；只有主堆挂着名牌，被吸的两堆全程不带名牌。
- 已有逻辑堆（总量 >64）旁边再掉一堆小的：逻辑堆位置不变，总量增加，名牌数字跟着涨。
- 相距 5 格时不会合并，各自挂自己的名牌。带附魔光效的圆石（有数据组件）不会参与。
- 漏斗从逻辑堆下方抽取时一次拿 64 个，抽空可见栈后剩余总量仍留在原地。
- 服务器控制台不应出现本插件产生的 WARN。

## 限制

- 只合并**已经加载**的实体；未加载区块里的掉落物不会被扫描。
- 逻辑总量存在实体上：岩浆 / 火焰 / 爆炸销毁实体时，整堆（含未显示的余量）一起消失。
- 逻辑堆的可见栈是满堆，`/data` 或其它插件直接改 `Item.count` 时会被宿主按差值同步进总量。
- 每轮是「按总量贪心」的一次扫描，实体数量极大时开销会上升；靠降低白名单长度、半径、
  扫描频率控制。
- 聚拢是直线走过去，**不理方块阻挡**：隔着墙的两堆也会互相吸（旧版 `tp` 也是这样）。
  不想被吸就把半径调小，或给物品加 `nebula_nostack`。
- 不处理经验球、箭、船、矿车等非 `minecraft:item` 实体。
